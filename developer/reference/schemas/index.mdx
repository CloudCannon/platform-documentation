CloudCannon provides JSON Schemas for all configuration files, enabling autocomplete, validation, and inline documentation in your code editor.

All schemas are registered with <a href="https://github.com/SchemaStore/schemastore" target="_blank" rel="noopener noreferrer">SchemaStore</a>. The JSON and YAML language servers in most code editors read the SchemaStore catalog and apply the matching schema based on the filename. Schemas are published as release assets of the <a href="https://github.com/CloudCannon/configuration-types" target="_blank" rel="noopener noreferrer">@cloudcannon/configuration-types</a> package on GitHub.

## Available schemas

All schemas are published under `https://github.com/cloudcannon/configuration-types/releases/latest/download/`.

### Configuration File schemas

<comp.OptionsTable>
  <comp.OptionsRow label="cloudcannon-config.schema.json" href="https://github.com/cloudcannon/configuration-types/releases/latest/download/cloudcannon-config.schema.json">
    Your main *Configuration File*.

    *Validates:* `cloudcannon.config.yml`, `cloudcannon.config.yaml`, `cloudcannon.config.json`

Split configuration files are matched by their extension. The extension names the kind of configuration the file holds, so a file referenced by `collections_config_from_glob` ends in `.cloudcannon.collections.yml` (for example, `posts.cloudcannon.collections.yml`). Each extension below also matches with `.yaml` or `.json` in place of `.yml`.

### Non-unified configuration SSG-specific schemas

For older *Sites* using the non-unified configuration format, the registered *Configuration File* schema also covers the SSG-specific legacy formats. Set the `version` key in your *Configuration File* to select which one applies:

- `legacy-jekyll`
- `legacy-hugo`
- `legacy-eleventy`
- `legacy-reader` (other SSGs using CloudCannon Reader)

<comp.MultiCodeBlock language="YAML" translate_into={["json"]} source="cloudcannon.config.yml">
```
version: legacy-jekyll
```
</comp.MultiCodeBlock>

When `version` is omitted or set to `latest`, the unified configuration schema applies.

We recommend [migrating to Unified Configuration](/documentation/developer-guides/unified-configuration-migration-guide/) to benefit from the latest features.

## IDE configuration

Most code editors apply the schemas automatically through their JSON and YAML language servers. If you use a custom path for your *Configuration File*, SchemaStore cannot match it by filename. Each language server has its own setting for associating a schema with a file, so you can add the mapping there instead of in the file itself.

### VS Code and Cursor

JSON files work automatically with no setup required. YAML files require the <a href="https://marketplace.visualstudio.com/items?itemName=redhat.vscode-yaml" target="_blank" rel="noopener noreferrer">Red Hat YAML extension</a>, which also applies schemas from SchemaStore automatically once installed.

To apply the schema to a custom *Configuration File* path, add a mapping to the `json.schemas` or `yaml.schemas` setting in your `settings.json`:

<comp.CodeBlock language="json" source=".vscode/settings.json">
```
{
  "yaml.schemas": {
    "https://github.com/cloudcannon/configuration-types/releases/latest/download/cloudcannon-config.schema.json": "config/cms.yml"
  }
}
```
</comp.CodeBlock>

For more information, see the <a href="https://code.visualstudio.com/docs/languages/json#_json-schemas-and-settings" target="_blank" rel="noopener noreferrer">VS Code JSON Schema documentation</a>.

### JetBrains IDEs

WebStorm, IntelliJ IDEA, and other JetBrains IDEs have built-in JSON and YAML schema support that works automatically via SchemaStore integration.

To associate a schema manually, open *JSON Schema Mappings* under *Languages & Frameworks* in the IDE settings. See the <a href="https://www.jetbrains.com/help/idea/json.html#ws_json_schema_add_custom" target="_blank" rel="noopener noreferrer">JetBrains JSON Schema documentation</a> for details.

### Sublime Text

Install the <a href="https://packagecontrol.io/packages/LSP" target="_blank" rel="noopener noreferrer">LSP</a> and <a href="https://packagecontrol.io/packages/LSP-json" target="_blank" rel="noopener noreferrer">LSP-json</a> packages for JSON schema support. Schemas are automatically discovered via SchemaStore. For YAML files, also install <a href="https://packagecontrol.io/packages/LSP-yaml" target="_blank" rel="noopener noreferrer">LSP-yaml</a>.

### Neovim

Use <a href="https://github.com/neovim/nvim-lspconfig" target="_blank" rel="noopener noreferrer">nvim-lspconfig</a> with `jsonls` for JSON files and `yamlls` for YAML files. Both language servers automatically discover schemas through SchemaStore.

### Zed

Zed has built-in JSON schema support that works automatically via SchemaStore. See the <a href="https://zed.dev/docs/languages/json" target="_blank" rel="noopener noreferrer">Zed JSON documentation</a> for more details.
