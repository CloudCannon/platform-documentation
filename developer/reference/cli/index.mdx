The CloudCannon Command Line Interface (CLI) lets you work with CloudCannon from the command line. It generates and validates CloudCannon configuration files, runs a local dev server that loads the CloudCannon app against your local files, and manages your <comp.GlossaryTerm term="/user/glossary/o/organization.yml">Organizations</comp.GlossaryTerm>, <comp.GlossaryTerm term="/user/glossary/s/site.yml">Sites</comp.GlossaryTerm>, <comp.GlossaryTerm term="/user/glossary/b/build.yml">Builds</comp.GlossaryTerm>, files, and form submissions via the CloudCannon <comp.GlossaryTerm term="/user/glossary/a/api.yml">API</comp.GlossaryTerm>.

## Installation

Install the CLI globally with npm:

```sh
npm install --global @cloudcannon/cli
```

The CLI requires Node.js 24 or later.

## Authentication

The `configure` and `dev` commands work on your local project files and don't require authentication. The `sites`, `orgs`, `builds`, and `inboxes` commands operate on CloudCannon through the API, so they require authentication.

For interactive use, log in with your CloudCannon account:

```sh
cloudcannon login
```

For automation and continuous integration, provide a credential through environment variables instead:

* `CLOUDCANNON_API_KEY` — an organization-scoped <comp.GlossaryTerm term="/user/glossary/a/api-key.yml">API Key</comp.GlossaryTerm>
* `CC_ACCESS_KEY_ID` and `CC_ACCESS_KEY_SECRET` — a personal <comp.GlossaryTerm term="/user/glossary/a/access-key.yml">Access Key</comp.GlossaryTerm>

To create these credentials, please read our documentation on [creating an API key](/documentation/developer-articles/create-an-api-key/) or [creating an Access Key](/documentation/developer-articles/create-an-access-key/). Store them as secret environment variables, and never commit them to source control.
