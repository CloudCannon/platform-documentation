The CloudCannon <comp.GlossaryTerm term="/user/glossary/a/api.yml">API</comp.GlossaryTerm> lets you manage your <comp.GlossaryTerm term="/user/glossary/o/organization.yml">Organizations</comp.GlossaryTerm>, <comp.GlossaryTerm term="/user/glossary/p/project.yml">Projects</comp.GlossaryTerm>, <comp.GlossaryTerm term="/user/glossary/s/site.yml">Sites</comp.GlossaryTerm>, <comp.GlossaryTerm term="/user/glossary/b/build.yml">Builds</comp.GlossaryTerm>, and more programmatically. This reference is generated from the CloudCannon OpenAPI specification and covers every available endpoint, grouped by resource.

<comp.Notice info_type="important">
  The API is versioned under the `/api/v0/` path. While it is on a `v0` version, endpoints and fields may change. Deprecated endpoints are marked in this reference.
  
  If CloudCannon changes an endpoint you use, you will receive an email alert. However, we recommend using the [SDK](/documentation/developer-reference/sdk/), which we update to match changes to the API.
</comp.Notice>

## Working with the API

The recommended way to work with the CloudCannon API is through one of our official tools. They handle authentication, request signing, and pagination for you, so reach for these before calling the HTTP endpoints directly:

- [CloudCannon CLI](/documentation/developer-reference/cli/) — manage your *Organizations*, *Sites*, *Builds*, files, and form submissions from the terminal.
- [TypeScript SDK](/documentation/developer-reference/sdk/) — a typed client with a sub-client for each resource and built-in pagination, sorting, and filtering.

If you need direct access — for another language, or a use case the tools don't cover — the rest of this reference documents the underlying HTTP API.

## Authentication

Every request must be authenticated. The CloudCannon API supports two types of credentials:

- **<comp.GlossaryTerm term="/user/glossary/a/api-key.yml">API Keys</comp.GlossaryTerm>** — scoped to an *Organization*. Best for server-to-server integrations, and the method this reference documents.
- **<comp.GlossaryTerm term="/user/glossary/a/access-key.yml">Access Keys</comp.GlossaryTerm>** — scoped to an individual user. Created and used by the CloudCannon CLI to act on that user's behalf.

<comp.Notice info_type="info">
  These are not the same as a [Bearer Token](/documentation/developer-articles/generate-a-bearer-token/), which controls access to content on a hosted *Site* and is not used to authenticate the CloudCannon API.
</comp.Notice>

### API Keys

An *API Key* authenticates as an *Organization* and grants access to that *Organization's* resources, limited to the permissions granted to the key when it was created. A request for an action the key doesn't have permission for returns `403 Forbidden`. To create one, please read our documentation on [creating an API key](/documentation/developer-articles/create-an-api-key/), then pass it in the `X-API-KEY` header on every request:

<comp.CodeBlock language="bash" source="Terminal">
```bash
curl https://app.cloudcannon.com/api/v0/orgs \
  -H "X-API-KEY: <your-api-key>"
```
</comp.CodeBlock>

Keep your *API Key* on your server. It grants access to your *Organization*, so never expose it in client-side code or commit it to source control.

Many endpoints are scoped to an *Organization* and include its *Organization UUID* in the path. Your *Organization UUID* appears alongside your keys on the *API Keys* page.

### Access Keys

An *Access Key* authenticates as an individual user, with that user's permissions across the *Organizations* they belong to. *Access Keys* are created when you authenticate the CloudCannon CLI by running `cloudcannon login`, and can be [managed or revoked](/documentation/developer-articles/create-an-access-key/) from *Account Settings → Access Keys*. Requests made with an *Access Key* are cryptographically signed; the CLI and SDK handle this for you.

For direct HTTP access we recommend using an *API Key*. If you need to sign *Access Key* requests in another language, see the <a href="https://github.com/CloudCannon/sdk/blob/main/index.ts" target="_blank" rel="noopener noreferrer">signRequest method in the SDK</a> for a reference implementation of the signing scheme.

Requests without valid credentials return a `401 Unauthorized` response.

## Pagination

List endpoints accept `page` and `items` query parameters to page through results, and `sort_attribute` and `sort_direction` to control ordering. `sort_direction` accepts `ASC` or `DESC` and defaults to `DESC`. The available `sort_attribute` values vary by endpoint and are listed with each endpoint's parameters.

<comp.CodeBlock language="bash" source="Terminal">
```bash
curl "https://app.cloudcannon.com/api/v0/orgs/<org_uuid>/sites?page=2&items=50" \
  -H "X-API-KEY: <your-api-key>"
```
</comp.CodeBlock>

## Rate limiting

Requests to the API are rate limited by IP address. Requests over the limit receive a `429 Too Many Requests` response — back off and retry when you get one. Because the limit is per IP address, requests that share an IP (for example, several keys running from the same CI server) count against the same limit.
