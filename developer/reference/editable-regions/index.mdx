An *Editable Region* in the Visual Editor allows you to edit your files inline on a preview of your webpage generated at build time. *Editable Regions* are indicated by a yellow box, and can be one of the following types: [Text](/documentation/developer-articles/configure-text-editable-regions/), [Image](/documentation/developer-articles/configure-image-editable-regions/), [Source](/documentation/developer-articles/configure-source-editable-regions/), [Array and Array Item](/documentation/developer-articles/configure-array-editable-regions/), or [Component](/documentation/developer-articles/configure-component-editable-regions/).

This article covers all HTML attributes available for configuring *Editable Regions* in the Visual Editor. For more information, please read our documentation on [Editable Regions](/documentation/articles/what-are-editable-regions/) in general or follow the [Set up Visual Editing](/documentation/developer-guides/set-up-visual-editing/) guide.

<comp.OptionsTable>
  <comp.OptionsRow label="data-editable" type_markdown="HTML Attribute">
    This HTML attribute defines the type of *Editable Region* that CloudCannon should use in the Visual Editor. You can add this HTML attribute to a DOM element in any file type as long as it outputs to an HTML file after a *Site* build.

    Values can be one of the following: `text`, `image`, `source`, `array`, `array-item`, or `component`.

    Depending on the value of this HTML element, the Visual Editor will also require other HTML attributes for *Editable Regions* to function.

    If there is no appropriate DOM element, you can wrap elements in the equivalent web component, which will accept HTML attributes. The web component can be one of the following: `<editable-text>`, `<editable-image>`, `<editable-source>`, `<editable-array>`, `<editable-array-item>`, or `<editable-component>`.

    This HTML attribute, or the equivalent web component, is required for all <em>Editable Regions</em>.

    <comp.Example>
      In this example, we have added `data-editable="text"` HTML attribute to the `<h1>` tag to define a Text *Editable Region*.

      <comp.CodeBlock language="Astro"  source="file.astro">
                  ``````````
                  <html lang="en">
                    <body>
                      <main>
                        <article>
                          <h1 data-editable="text" data-prop="title" >{title}</h1>
                        </article>
                      </main>
                    </body>
                  </html>
                  ``````````
                  </comp.CodeBlock>

      In this example, we have wrapped the `<slot />` element in the `<editable-text>` web component to define a Text *Editable Region*, as no DOM element was available.

      <comp.CodeBlock language="Astro"  source="file.astro">
                  ``````````
                  <html lang="en">
                    <body>
                      <main>
                        <article>
                          <editable-text data-prop="@content">
                            <slot />
                          </editable-text>
                        </article>
                      </main>
                    </body>
                  </html>

                  ``````````
                  </comp.CodeBlock>
    </comp.Example>
  </comp.OptionsRow>
  <comp.OptionsRow label="data-prop" type_markdown="HTML Attribute">
    This HTML attribute defines the path to the structured data key you want to edit. CloudCannon will pass the value of that key to your <em>Editable Region</em> so the Visual Editor can re-render that section of your webpage preview.

    Values can be one of the following: a key from your front matter, `@content` for the Markdown content of your file, `@collections[name].index.key` for a key from a specific <em>Collection</em>, `@data[filename].key`, or `@file[path].key` for a key from a specific file. You can combine `@file[path]` with `@content` to edit the Markdown content of another file (i.e., `@file[path].@content`).

    Array and Array Item <em>Editable Regions</em> also provide two values from the structure of your array, rather than from your data. An Array <em>Editable Region</em> provides `@length`, the number of items in the array. An Array Item <em>Editable Region</em> provides `@index`, the position of that item. Reference either value from an <em>Editable Region</em> nested inside, using `data-prop` or a `data-prop-*` HTML attribute.

    For Image <em>Editable Regions</em>, `data-prop` can select an object containing the `src`, `alt`, and `title` keys, instead of binding each value with a separate `data-prop-*` attribute.

    This HTML attribute is required for Text and Array <em>Editable Regions</em>.

    <comp.Example>
      In this example, we have added `data-prop="title"` HTML attribute to the `<h1>` tag. CloudCannon will pass the value of the `title` structured data key to the Text *Editable Region* and re-render any changes in the Visual Editor.

      <comp.CodeBlock language="Astro"  source="file.astro">
                  ``````````
                  <html lang="en">
                    <body>
                      <main>
                        <article>
                          <h1 data-editable="text" data-prop="title" >{title}</h1>
                        </article>
                      </main>
                    </body>
                  </html>

                  ``````````
                  </comp.CodeBlock>
      <comp.CodeBlock language="Markdown"  source="blog.mdx">
                  ``````````
                  ---
                  title: Our new project
                  author: H. Scott
                  banner_image: /assets/banner.jpg
                  date: 2025-08-26T11:17:02+12:00
                  ---
                  Content goes here.

                  ``````````
                  </comp.CodeBlock>
      In this example, we have added `data-prop="@file[about.md].@content"` HTML attribute to the `<editable-text>` web component. CloudCannon will pass the Markdown content of the `about.md` file to the Text *Editable Region*, allowing your team to edit that file without leaving this webpage.

      <comp.CodeBlock language="Astro"  source="file.astro">
                  ``````````
                  <html lang="en">
                    <body>
                      <main>
                        <article>
                          <editable-text data-prop="@file[about.md].@content">
                            <Content />
                          </editable-text>
                        </article>
                      </main>
                    </body>
                  </html>

                  ``````````
                  </comp.CodeBlock>
      In this example, we have added `data-prop-position="@index"` HTML attribute to the `<editable-component>` web component inside our Array Item *Editable Region*. CloudCannon will pass the position of each array item to the registered `testimonial_card` component under the `position` key.

      <comp.CodeBlock language="Astro"  source="file.astro">
                  ``````````
                  <ul data-editable="array" data-prop="testimonials">
                    {
                      testimonials.map((testimonial, index) => (
                        <li data-editable="array-item">
                          <editable-component
                            data-component="testimonial_card"
                            data-prop-position="@index"
                          >
                            <TestimonialCard {...testimonial} position={index} />
                          </editable-component>
                        </li>
                      ))
                    }
                  </ul>

                  ``````````
                  </comp.CodeBlock>
      In this example, we have added `data-prop="banner"` HTML attribute to the `<img>` tag. The `banner` structured data key is an object containing the `src`, `alt`, and `title` keys, so CloudCannon passes all three values to the Image *Editable Region* without a separate `data-prop-*` attribute for each.

      <comp.CodeBlock language="Astro"  source="file.astro">
                  ``````````
                  <img
                    data-editable="image"
                    data-prop="banner"
                    src={banner.src}
                    alt={banner.alt}
                    title={banner.title}
                  />

                  ``````````
                  </comp.CodeBlock>
      <comp.CodeBlock language="Markdown"  source="blog.mdx">
                  ``````````
                  ---
                  title: Our new project
                  banner:
                    src: /assets/banner.jpg
                    alt: A wide banner showing our new product
                    title: Our new product
                  ---
                  Content goes here.

                  ``````````
                  </comp.CodeBlock>
    </comp.Example>

  <comp.OptionsRow label="data-prop-*" type_markdown="HTML Attribute">
    This HTML attribute defines the path to the structured data key you want to edit and the key name when passing the value to an *Editable Region*. CloudCannon will pass the value of that key and relabel it with a new key name to your *Editable Region* so the Visual Editor can re-render that section of your webpage preview.

    This HTML attribute is an extension of the behavior of `data-prop`.

    Image <em>Editable Regions</em> must contain an `<img>` element, either as the element itself or as a child. If the `<img>` is inside a `<picture>` element, CloudCannon also updates the `src` and `srcset` of any `<source>` elements when the image changes.

    This HTML attribute is required for Image <em>Editable Regions</em>, unless you have defined `data-prop`.

    <comp.Example>
      In this example, we have added `data-prop-src="banner_image"` HTML attribute to the `<img>` tag. CloudCannon will pass the value of the `banner_image` structured data key to the Image *Editable Region* with the label `src` (i.e., `src: /assets/banner.jpg`) and re-render any changes in the Visual Editor.

      <comp.CodeBlock language="Astro"  source="file.astro">
                  ``````````
                  <html lang="en">
                    <body>
                      <main>
                        <article>
                          <div>
                              {banner_image &&
                                <img
                                  data-editable="image"
                                  data-prop-src="banner_image"
                                  src={banner_image}
                                />
                              }
                          </div>
                        </article>
                      </main>
                    </body>
                  </html>

                  ``````````
                  </comp.CodeBlock>
      <comp.CodeBlock language="Markdown"  source="blog.mdx">
                  ``````````
                  ---
                  title: Our new project
                  author: H. Scott
                  banner_image: /assets/banner.jpg
                  date: 2025-08-26T11:17:02+12:00
                  ---
                  Content goes here.

                  ``````````
                  </comp.CodeBlock>
    </comp.Example>

  <comp.OptionsRow label="data-literal-*" type_markdown="HTML Attribute">
    This HTML attribute passes a literal value to an *Editable Region*, rather than selecting a value from your data. Use it for values that do not live in any file, such as a fixed label or a display option.

    The attribute suffix is the key name CloudCannon passes the value under. CloudCannon lowercases this key name, so `data-literal-author-name` passes the value under `authorname`. We recommend single-word key names to avoid confusion.

    Values that parse as JSON are passed as structured values. Any other value is passed as a string.

    You can also use `data-literal` on its own to pass a literal value as the entire value of the *Editable Region*, rather than under a key name.

    This HTML attribute is optional for all <em>Editable Regions</em>, and is most useful for Component <em>Editable Regions</em>.

    <comp.Example>
      In this example, we have added `data-literal-variant="compact"` to the `<editable-component>` web component. CloudCannon will pass `variant: "compact"` to the registered `author_card` component, alongside the `author` structured data, and re-render the component in the Visual Editor.

      <comp.CodeBlock language="Astro"  source="file.astro">
                  ``````````
                  <html lang="en">
                    <body>
                      <main>
                        <article>
                          <editable-component
                            data-prop="author"
                            data-component="author_card"
                            data-literal-variant="compact"
                          >
                            <AuthorCard {...author} variant="compact" />
                          </editable-component>
                        </article>
                      </main>
                    </body>
                  </html>

                  ``````````
                  </comp.CodeBlock>
      <comp.CodeBlock language="Markdown"  source="blog.mdx">
                  ``````````
                  ---
                  title: Our new project
                  author:
                    name: H. Scott
                    role: Support engineer
                  date: 2025-08-26T11:17:02+12:00
                  ---
                  Content goes here.

                  ``````````
                  </comp.CodeBlock>
    </comp.Example>
  </comp.OptionsRow>
  <comp.OptionsRow label="data-path" type_markdown="HTML Attribute">
    This HTML attribute defines the path to the file you want to edit. CloudCannon will pass the value of that key to your <em>Editable Region</em> so the Visual Editor can re-render that section of your webpage preview.

    This HTML attribute is required for Source <em>Editable Regions</em>.

    <comp.Example>
      In this example, we have added the `data-path="/src/pages/index.astro"` HTML attribute to the `<main>` tag. CloudCannon will pass the value of the file to the Source *Editable Region* and re-render any changes in the Visual Editor.

      <comp.CodeBlock language="Astro" source="index.astro">
                  ``````````
                  <html lang="en">
                    <body>
                      <main data-editable="source" data-path="/src/pages/index.astro" data-key="main">
                        <img src="/smiling-robot.jpg">
                        <h1>Hello!</h1>
                      <p>
                            Lorem ipsum dolor sit amet, consectetur adipiscing elit, sed do eiusmod tempor incididunt ut
                  ``````````

  <comp.OptionsRow label="data-type" type_markdown="HTML Attribute">
    This HTML attribute defines which rich text formatting options are available for a Text <em>Editable Region</em>.

    Values can be one of the following: `span` for plain text, `text` for paragraph-level rich text, or `block` for multi-paragraph rich text.

    By default, `data-type` is `block` or `text` for any Source <em>Editable Regions</em>, `data-prop="@content"`, or Rich Text Inputs, and `span` where Input type is not Rich Text, or is not configured.

    This HTML attribute is optional for Text <em>Editable Regions</em>.

    <comp.Example>
      In this example, we have added the `data-type="block"` HTML attribute to the `<editable-text>` web component, as we want all rich text formatting options.

      <comp.CodeBlock language="Astro" source="file.astro">
                  ``````````
                  <editable-text data-prop="title" data-type="block">Default text</editable-text>

                  ``````````
                  </comp.CodeBlock>
    </comp.Example>
  </comp.OptionsRow>
  <comp.OptionsRow label="data-defer-mount" type_markdown="HTML Attribute">
    This HTML attribute toggles whether the Visual Editor will automatically load an <em>Editable Region</em>. When set to true, CloudCannon will only initialize the <em>Editable Region</em> when clicked.

    By default, this key is false (i.e., the Visual Editor will not defer loading the <em>Editable Region</em>).

    This HTML attribute is optional for Text <em>Editable Regions</em>.
  </comp.OptionsRow>
  <comp.OptionsRow label="data-key" type_markdown="HTML Attribute">
    This HTML attribute defines the unique identifier for a Source <em>Editable Region</em>, so CloudCannon can update the correct one if you have several in one file.

    This HTML attribute is required for Source <em>Editable Regions</em>.

    <comp.Example>
      In this example, we have added the `data-key` HTML attribute to both `<section>` tags, with a different value for each <em>Editable Regions</em>.

      <comp.CodeBlock language="Astro" source="file.astro">

                  ``````````
                          <h1>Hello!</h1>
                        </section>
                        <section data-editable="source" data-path="/src/pages/index.astro" data-key="content">
                  ``````````

  <comp.OptionsRow label="data-id-key" type_markdown="HTML Attribute">
    This HTML attribute defines the path to the structured data key where `data-id` is defined. Must be used in conjunction with `data-id` on Array Item <em>Editable Regions</em>.

    This HTML attribute is optional for simple Array <em>Editable Regions</em>, but required for complex Array <em>Editable Regions</em> (i.e., the array items do not share the same structure).

    <comp.Example>
      In this example, we have added `data-id-key="_name"` to the `<section>` tag. For each Array Item in this Array <em>Editable Region</em>, CloudCannon will look for the `data-id` under the `_name` key.

      <comp.CodeBlock language="Astro" source="file.astro">
                  ``````````
                  <html lang="en">
                    <body>
                      <main>
                        <section data-prop="contentBlocks" data-id-key="_name" data-component-key="_name">
                          {
                            contentBlocks.map((block) => {
                              const Component = components[block._name];
                              return <editable-array-item data-id={block._name} data-component={block._name}><Component {...block} /></editable-array-item>;
                            })
                          }
                        </section>
                      </main>
                    </body>
                  </html>
                  ``````````
                  </comp.CodeBlock>
    </comp.Example>
  </comp.OptionsRow>
  <comp.OptionsRow label="data-id" type_markdown="HTML Attribute">
    This HTML attribute defines the unique ID of an Array Item. The value of `data-id` should be templating containing the name of the structured data key, which CloudCannon will populate at build time. Must be used in conjunction with `data-id-key` on Array <em>Editable Regions</em>.

    This HTML attribute is optional for simple Array <em>Editable Regions</em>, but required for complex Array <em>Editable Regions</em> (i.e., the array items do not share the same structure).
    <comp.Example>
                  In this example, we have added `data-id={block._name}` to the `<editable-array-item>` web component. For each Array Item in this Array <em>Editable Region</em>, CloudCannon will populate the `data-id` attribute with the value of the `block._name` key.

      <comp.CodeBlock language="Astro" source="file.astro">
                  ``````````
                  <html lang="en">
                    <body>
                      <main>
                        <section data-prop="contentBlocks" data-id-key="_name" data-component-key="_name">
                          {
                            contentBlocks.map((block) => {
                              const Component = components[block._name];
                              return <editable-array-item data-id={block._name} data-component={block._name}><Component {...block} /></editable-array-item>;
                            })
                          }
                        </section>
                      </main>
                    </body>
                  </html>
                  ``````````
                  </comp.CodeBlock>
    </comp.Example>

  <comp.OptionsRow label="&lt;template&gt;" type_markdown="HTML Element">
    This HTML element defines the markup CloudCannon should use when your team adds a new item to an Array <em>Editable Region</em>. Place the `<template>` element inside your Array <em>Editable Region</em>.

    A `<template>` element with no `data-id` HTML attribute is the blueprint for every new array item. To use a different blueprint for each type of array item, add the `data-id` HTML attribute to each `<template>` element, matching the values of the key named by `data-id-key`. CloudCannon uses an unkeyed `<template>` element as the fallback for any array item without a matching blueprint.

    If your `<template>` element contains more than one root element, CloudCannon wraps its contents in an `<editable-array-item>` web component.

    This HTML element is optional. If your Array <em>Editable Region</em> defines a component, CloudCannon renders new array items with that component instead. If there is neither a `<template>` element nor a component, CloudCannon copies the markup of an existing array item. An empty array with neither a `<template>` element nor a component will display an error in the Visual Editor.

    <comp.Example>
      In this example, we have added two `<template>` elements to our Array *Editable Region*, each with a `data-id` HTML attribute matching a value of the `type` structured data key. When your team adds a "hero" array item, CloudCannon renders the markup in the matching `<template>` element.

      <comp.CodeBlock language="Astro"  source="file.astro">
                  ``````````
                  <ul data-editable="array" data-prop="blocks" data-id-key="type">
                    <template data-id="hero">
                      <li>
                        <h2 data-editable="text" data-prop="title"></h2>
                      </li>
                    </template>
                    <template data-id="quote">
                      <li>
                        <blockquote data-editable="text" data-prop="quote"></blockquote>
                      </li>
                    </template>
                  </ul>

                  ``````````
                  </comp.CodeBlock>
    </comp.Example>
  </comp.OptionsRow>
  <comp.OptionsRow label="data-direction" type_markdown="HTML Attribute">
    This HTML attribute defines the behavior of the Array <em>Editable Region</em> when dragging items in the Visual Editor. CloudCannon displays a yellow line to indicate where it will insert an array item when dragging and dropping. You can match the direction of the array on your webpage by defining this HTML attribute.

    Values can be one of the following: `column` for vertical ascending order, `row` for horizontal ascending order, `column-reverse` for vertical descending order, and `row-reverse` for horizontal descending order.

    By default, `data-direction` is `column` (i.e., a vertical array with array position one at the top).

    This HTML attribute is optional for Array <em>Editable Regions</em>.
    <comp.Example>
      In this example, we have added `data-direction=row` to the `<ul>` tag, as the array on our webpage is horizontal, with array position one on the left. This way, CloudCannon will highlight the left and right edges of array items to indicate where an array item will be moved to when dragging and dropping.

      <comp.CodeBlock language="Astro" source="file.astro">
                  ``````````
                  <html lang="en">
                    <body>
                      <main>
                        <section>
                          <ul data-editable="array" data-prop="testimonials" data-direction="row">
                            {
                              testimonials.map((testimonial) => (
                                <li data-editable="array-item" >
                                  <p>{testimonial.quote}</p>
                                </li>
                              ))
                            }
                          </ul>
                        </section>
                      </main>
                    </body>
                  </html>
                  ``````````
                  </comp.CodeBlock>
    </comp.Example>
  </comp.OptionsRow>

  <comp.OptionsRow label="data-component" type_markdown="HTML Attribute">
    This HTML attribute defines which registered component an Array, Array Item, or Component <em>Editable Region</em> should reference. The value of `data-component` should be the same name as the component in your registration script.

    On an Array <em>Editable Region</em>, `data-component` acts as a fallback. CloudCannon uses it to render any array item that does not resolve a component from the key named by `data-component-key`. This is useful when every item in your array uses the same component.

    This HTML attribute is optional for simple Array <em>Editable Regions</em>, but required for Component <em>Editable Regions</em> and complex Array <em>Editable Regions</em> (i.e., the array items do not share the same structure).
    <comp.Example>
                  In this example, we have added `data-component="cta"` to the `<editable-component>` web component, using the same name as the `cta` component in our registration script.

      <comp.CodeBlock language="Astro" source="file.astro">
                  ``````````
                  <editable-component data-prop="cta" data-component="cta">
                    <CTA {...Astro.props.cta} />
                  </editable-component>
                  ``````````
                  </comp.CodeBlock>

      <comp.CodeBlock language="Astro" source="file.astro">
                  ``````````
                  import { registerAstroComponent } from '@cloudcannon/editable-regions/astro';
                  import CTA from '../components/CTA.astro';

                  // Register your components
                  registerAstroComponent('cta', CTA);
                  ``````````
                  </comp.CodeBlock>

                  In this example, we have added `data-component={block._name}` to the `<editable-array-item>` web component, so that it will populate with the name of the component in our registration script at build time.

      <comp.CodeBlock language="Astro" source="file.astro">
                  ``````````
                  <html lang="en">
                    <body>
                      <main>
                        <section data-prop="contentBlocks" data-id-key="_name" data-component-key="_name">
                          {
                            contentBlocks.map((block) => {
                              const Component = components[block._name];
                              return <editable-array-item data-id={block._name} data-component={block._name}><Component {...block} /></editable-array-item>;
                            })
                          }
                        </section>
                      </main>
                    </body>
                  </html>
                  ``````````
                  </comp.CodeBlock>
    </comp.Example>

  <comp.OptionsRow label="data-cloudcannon-ignore" type_markdown="HTML Attribute">
    This HTML attribute instructs CloudCannon to ignore the `data-editable` HTML attribute if you do not want <em>Editable Regions</em>.

    <comp.Example>

      <comp.CodeBlock language="Astro" source="file.astro">
                  ``````````
                  <html lang="en">
                    <body>
                      <main>
                        <article>
                          <h1 data-editable="true" data-cloudcannon-ignore >{title}</h1>
                        </article>
                      </main>
                    </body>
                  </html>
                  ``````````
                  </comp.CodeBlock>
    </comp.Example>
