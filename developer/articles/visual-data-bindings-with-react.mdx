React passes `data-` attributes straight through to the DOM, so adding `data-cms-bind` to an element works the same as it does in plain HTML, and CloudCannon draws the same editing overlays over it in the <comp.GlossaryTerm term="/user/glossary/v/visual-editor.yml">Visual Editor</comp.GlossaryTerm>. For the attribute's syntax, please read our documentation on [what Visual Data Bindings are](/documentation/developer-articles/what-are-visual-data-bindings/).

The part React adds is threading the path. A binding names a value's full path from the root of your data, but a reusable component has no way of knowing where in that structure it has been placed. The component above it does, so pass the path down as a prop.

Bindings mark up what is editable. They do not re-render your components when the data changes: for that, please read our documentation on [using Visual Data Previews with React](/documentation/developer-articles/visual-data-previews-with-react/).

## Passing binding paths through components

Give each component a prop holding its own path, and build child bindings from it.

<comp.CodeBlock language="jsx" source="hero.jsx">
```
function Hero({ path, data }) {
  const bind = (key) => [path, key].filter(Boolean).join('.'); /*1*/

  return (
    <section>
      <h1 data-cms-bind={bind('title')}>{data.title}</h1>
      <p data-cms-bind={bind('subtitle')}>{data.subtitle}</p>
    </section>
  );
}
```
<comp.Annotation number="1">

Joining with `filter(Boolean)` drops an empty path, so a component placed at the root produces `title` rather than `.title`.

</comp.Annotation>
</comp.CodeBlock>

The parent passes the path it occupies, and a component rendered at the root of your data passes an empty string.

<comp.CodeBlock language="jsx" source="page.jsx">
```
<Hero path="hero" data={page.hero} />
<Hero path="" data={page} /> /*1*/
```
<comp.Annotation number="1">

An empty path is a valid value to pass down, because `bind()` discards it when building child bindings.

</comp.Annotation>
</comp.CodeBlock>

## Never render an empty binding

An empty path is fine to pass as a prop, but it must never reach the DOM as an attribute. CloudCannon treats `data-cms-bind=""` as a binding it cannot resolve: the element still gets an overlay in the *Visual Editor*, bound to a field named `unset` that does not exist in your data.

Render the attribute only when the component has a path.

<comp.CodeBlock language="jsx" source="hero.jsx">
```
function Hero({ path, data }) {
  const bind = (key) => [path, key].filter(Boolean).join('.');

  return ( /*1*/
    <section {...(path ? { 'data-cms-bind': path } : {})}>
      <h1 data-cms-bind={bind('title')}>{data.title}</h1>
    </section>
  );
}
```
<comp.Annotation number="1">

Spreading a conditional object adds the attribute when `path` has a value and omits it entirely when `path` is empty.

</comp.Annotation>
</comp.CodeBlock>

## Arrays

Every binding you nest adds a click, because a child binding only becomes selectable once its parent is selected. Where you have an array component rendering an item component, binding both means two clicks to reach an item.

Bind the items and leave the array container unbound. The items keep their reordering and removal controls, and a <comp.GlossaryTerm term="/user/glossary/t/team-member.yml">Team Member</comp.GlossaryTerm> reaches them one click sooner.
