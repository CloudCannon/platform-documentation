<comp.Notice info_type="permissions">
  **Permissions required**

  Members of the *Owners* and *Developers* [Default Permission Groups](/documentation/user-articles/what-are-default-permission-groups/), or [Custom Permission Groups](/documentation/developer-articles/what-are-custom-permission-groups/) with the `org:settings:inbox:write` permission, can configure a CAPTCHA provider for an *Inbox*.
</comp.Notice>

A CAPTCHA embeds a challenge in your form that a visitor has to pass before CloudCannon accepts their submission. You choose one CAPTCHA provider for each <comp.GlossaryTerm term="/user/glossary/i/inbox.yml">Inbox</comp.GlossaryTerm>, and CloudCannon checks the CAPTCHA on submissions from each <comp.GlossaryTerm term="/user/glossary/s/site.yml">Site</comp.GlossaryTerm> that requires one.

Adding a CAPTCHA provider to an *Inbox* does not add a CAPTCHA to your *Site*. CloudCannon checks the CAPTCHA, but the provider's widget in your form is what shows it to the visitor, so a CAPTCHA takes three steps in different places: get keys from the provider, add them to your *Inbox*, then add the provider's widget to your form.

Before we begin, this article assumes you have already created the *Inbox* you want to protect. For more information, please read our documentation on [creating an Inbox](/documentation/developer-articles/create-an-inbox/).

Get your keys from the provider first, because the fields on your *Inbox* need them, and each field describes where to find its value. Each provider's page covers getting its keys, adding its widget, and testing it. For instructions per provider, please read our documentation on reducing spam with [Google reCAPTCHA](/documentation/developer-articles/reduce-spam-with-google-recaptcha/), [Google reCAPTCHA Enterprise](/documentation/developer-articles/reduce-spam-with-google-recaptcha/#recaptcha-enterprise), [hCaptcha](/documentation/developer-articles/reduce-spam-with-hcaptcha/), or [Cloudflare Turnstile](/documentation/developer-articles/reduce-spam-with-cloudflare-turnstile/).

<comp.Notice info_type="important">
  *Sites* linked to the *Inbox* with *Require Captcha* on start rejecting submissions that have no CAPTCHA response as soon as you save a provider. Add the widget to the forms on those *Sites* first, or turn off *Require Captcha* on them. CloudCannon warns you about this when you add a provider.
</comp.Notice>

To add a CAPTCHA provider to an *Inbox*:

1. Navigate to the *Forms* page under *Org Settings*.
2. Select the *Inbox* you want to protect.
3. Open the *Settings* tab.
4. Choose your provider in the *Captcha provider* dropdown.
5. Enter your keys in the fields that provider asks for.
6. Click the *Update Inbox* button.

CloudCannon will save the keys to your *Inbox* and start checking submissions from each *Site* that requires a CAPTCHA.

Alternatively, you can also choose a CAPTCHA provider when you create an *Inbox*, by clicking the *Add Inbox* button on the *Forms* page, entering your keys, and clicking the *Create inbox* button.

## CAPTCHA providers

The *Captcha provider* dropdown offers four providers, and each one asks for its own keys:

* *Google reCAPTCHA* takes a *Site key* and a *Secret key*, for reCAPTCHA v2 with a checkbox or invisible challenge, or reCAPTCHA v3 with an invisible, scored check. CloudCannon rejects a v3 token scoring below the *Minimum score*, which is 0.5 unless you change it.
* *Google reCAPTCHA Enterprise* takes a *Site key*, a *Google Cloud project ID*, and an *API key*, for reCAPTCHA keys in a Google Cloud project. CloudCannon rejects a token scoring below the *Minimum score*, when the key returns one.
* *hCaptcha* takes a *Site key* and a *Secret key*, for hCaptcha, which shows a checkbox challenge. Leave *Tell hCaptcha which site key to expect* on, so a token from a form on another of your hCaptcha sites is rejected.
* *Cloudflare Turnstile* takes a *Site key* and a *Secret key*, for Cloudflare Turnstile, which runs its checks in the background and asks some visitors to click a checkbox.

## Change your keys or provider

CloudCannon hides the secret key or API key once you save it, and never shows it again. The field shows *Secret key set* or *API key set* instead.

To replace a stored key:

1. Click the *Replace* button next to *Secret key set* or *API key set*.
2. Enter the new key.
3. Click the *Update Inbox* button.

CloudCannon will replace the stored key with the new one. To cancel before you save, click the *Keep the current secret key* or *Keep the current API key* button.

If you change the provider on an *Inbox* that already has keys, you need to enter the new provider's keys before you can save. The exception is a switch from *Google reCAPTCHA* to *Google reCAPTCHA Enterprise*, which keeps your *Site key*.

To stop checking CAPTCHAs, select *No captcha* in the *Captcha provider* dropdown and save the *Inbox*. CloudCannon warns you that saving removes the keys from the *Inbox*.

## Require the CAPTCHA on your Sites

CloudCannon only checks the CAPTCHA on submissions from a *Site* that requires it, using the *Require Captcha* option on the *Forms* page under *Site Settings*. For how to set that option when you link an *Inbox*, please read our documentation on [connecting your Site to an Inbox](/documentation/developer-articles/connect-your-site-to-an-inbox/).

*Require Captcha* is on by default when you link an *Inbox* that has a CAPTCHA provider. It was also on by default for older links, so a *Site* linked to the *Inbox* before you add a provider may already have it on.

If *Require Captcha* is on but the *Inbox* has no CAPTCHA provider, CloudCannon does not check submissions from that *Site*. The *Forms* page under *Site Settings* warns you when this happens.

## How CloudCannon checks each submission

Once a *Site* requires a CAPTCHA, CloudCannon handles each submission from it like this:

* If a submission has no CAPTCHA token, because the widget is missing or the visitor did not complete the challenge, CloudCannon returns a 401 error page to the visitor and does not store the submission.
* If your CAPTCHA provider rejects the token, CloudCannon stores the submission in the *Errored* category, does not send it to your <comp.GlossaryTerm term="/user/glossary/i/inbox-target.yml">Inbox Targets</comp.GlossaryTerm>, and redirects the visitor as usual.
* If CloudCannon cannot reach your CAPTCHA provider, or the provider does not respond within 10 seconds, CloudCannon stores the submission in the *Errored* category in the same way, rather than losing it.

Each token works once and expires after a few minutes. A form that resubmits an old token, for example after the visitor navigates back, fails verification.

CloudCannon also accepts the `_gotcha` honeypot field on any form, which catches untargeted spam without a CAPTCHA. For how to add the field to your form, please read our documentation on [the `_gotcha` honeypot](/documentation/developer-articles/create-a-form/#the-gotcha-honeypot).
