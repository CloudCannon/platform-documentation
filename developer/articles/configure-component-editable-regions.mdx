<comp.Notice info_type="permissions">
  <p><strong>Permissions required</strong></p><p>Members of the Owners, Developers, and Technical Editors <a href="/documentation/user-articles/what-are-default-permission-groups/">Default Permission Groups</a>, or <a href="/documentation/developer-articles/what-are-custom-permission-groups/">Custom Permission Groups</a> with the <code>site:source-editor:write</code> permission, can add <em>Editable Regions</em> to files using the Source Editor in CloudCannon.</p>
</comp.Notice>

<comp.GlossaryTerm term="/user/glossary/c/component-editable-region.yml">Component Editable Regions</comp.GlossaryTerm> are one type of [Editable Region](/documentation/developer-articles/what-are-editable-regions/) you can add to your layout and HTML-like files to enable visual editing. They allow you to re-render your components in the Visual Editor when you edit the values in the data panel or sidebar, and are also are also required to edit *Text* or <comp.GlossaryTerm term="/user/glossary/i/image-editable-region.yml">Image Editable Regions</comp.GlossaryTerm> nested inside a component.

Unlike other types of *Editable Region*, *Component Editable Regions* need an integration for your SSG, because CloudCannon runs your template code in the browser to re-render your components in the Visual Editor.

<comp.Notice info_type="info">
  <p>To avoid misconfiguration issues where CloudCannon cannot find the data property you want to edit, always add <em>Editable Regions</em> to values closest to the root of the file first (i.e., work from parent elements towards child elements).</p>
</comp.Notice>


These instructions assume you have configured your [build settings](/documentation/developer-articles/configure-your-first-build/) and are comfortable editing HTML layouts, either in CloudCannon's [Source Editor](/documentation/user-articles/what-is-the-source-editor/) or your local development environment.

## Install the integration for your SSG

CloudCannon provides an integration for Astro, Eleventy, and Hugo, and a root component for sites built with React, Vue, or Svelte, including Next.js, Nuxt, and SvelteKit. You only need to install this once per *Site*.

*Component Editable Regions* are not yet available for other SSGs. If you use another SSG, you can still use every other type of *Editable Region*. Please get in touch with our friendly <a href="https://cloudcannon.com/support/">support team</a> to request support for your SSG.

<comp.Tabs label="Static site generators">
  <comp.Tab name="Astro">
    ### Astro

    In Astro, you register each component you want to edit, then load your registration script when the page opens in the Visual Editor.

    1. Open your website project in your local development environment and run the `npm install @cloudcannon/editable-regions` command in your terminal.
    2. Import the *Editable Regions* integration in your Astro configuration file, `astro.config.mjs`.
    3. Create a registration file for your components (e.g., `src/scripts/register-components.js`) and register each component you want to edit.
    4. Import your registration file from your layout, inside the `<body>` element.
    5. Save your changes and rebuild your *Site*.

    <comp.CodeBlock language="JavaScript" source="astro.config.mjs">
    ``````````

    import editableRegions from "@cloudcannon/editable-regions/astro-integration";
    import { defineConfig } from "astro/config";

    export default defineConfig({
      integrations: [editableRegions()],
    });

    ``````````
    </comp.CodeBlock>

    <comp.CodeBlock language="JavaScript" source="src/scripts/register-components.js">
    ``````````

    import { registerAstroComponent } from '@cloudcannon/editable-regions/astro';
    import CTA from '../components/CTA.astro';

    registerAstroComponent('cta', CTA);

    ``````````
    </comp.CodeBlock>

    <comp.CodeBlock language="Astro" source="BlogPost.astro">
    ``````````

    <script> /*1*/
      if (window.inEditorMode) {
        import("../scripts/register-components.js").catch((error) => {
          console.warn("Failed to load CloudCannon component registration:", error);
        });
      }
    </script>

    ``````````
    <comp.Annotation number="1">

      The `window.inEditorMode` check means your registration script only loads when your webpage is open in CloudCannon's *Visual Editor*, so it never runs for your website visitors. For more information, please read our documentation on [detecting the Visual Editor](/documentation/developer-articles/detect-the-visual-editor/).

    </comp.Annotation>
    </comp.CodeBlock>

    If your Astro components contain React, Svelte, or Vue components, add the matching renderer to your registration file.

    <comp.CodeBlock language="JavaScript" source="src/scripts/register-components.js">
    ``````````

    import '@cloudcannon/editable-regions/astro-react-renderer';
    import '@cloudcannon/editable-regions/astro-svelte-renderer';
    import '@cloudcannon/editable-regions/astro-vue-renderer';

    ``````````
    </comp.CodeBlock>
  </comp.Tab>
  <comp.Tab name="Eleventy">
    ### Eleventy

    In Eleventy, there is no registration step. CloudCannon resolves component names the same way your templates resolve includes, so `{% include "author-card" %}` matches `data-component="author-card"`.

    1. Open your website project in your local development environment and run the `npm install @cloudcannon/editable-regions` command in your terminal.
    2. Add the *Editable Regions* plugin to your Eleventy configuration file.
    3. Import the generated registration script from your layout, inside the `<body>` element.
    4. Save your changes and rebuild your *Site*.

    <comp.CodeBlock language="JavaScript" source="eleventy.config.mjs">
    ``````````

    import editableRegions from "@cloudcannon/editable-regions/eleventy";

    export default function (eleventyConfig) {
      eleventyConfig.addPlugin(editableRegions);

      return {
        dir: { input: "src", includes: "_includes", output: "_site" },
      };
    }

    ``````````
    </comp.CodeBlock>

    After every build, the plugin writes a `register-components.js` file into your output directory. This file contains a browser version of the Liquid engine, your include templates, and your filters, shortcodes, and tags, copied from your Eleventy configuration file.

    <comp.CodeBlock language="HTML" source="base.liquid">
    ``````````

    <script>
      if (window.inEditorMode) {
        import("/register-components.js").catch((error) => {
          console.warn("Failed to load CloudCannon component registration:", error);
        });
      }
    </script>

    ``````````
    </comp.CodeBlock>

    The plugin also adds an `includeWith` tag, which passes an object to an include as separate values. Use this when your component data is a single structured data key.

    <comp.CodeBlock language="Liquid" source="post.liquid">
    ``````````

    <div data-editable="component" data-component="post-meta" data-prop="postMeta">
      {% includeWith "post-meta", postMeta %}
    </div>

    ``````````
    </comp.CodeBlock>

    <comp.Notice info_type="info">
      <p>Eleventy requires Node 20.19 or later.</p>
    </comp.Notice>
  </comp.Tab>
  <comp.Tab name="Hugo">
    ### Hugo

    Hugo uses a Hugo module rather than an NPM package. There is no registration step: CloudCannon resolves component names as partial names, so `data-component="card"` and `data-component="card.html"` both render `layouts/partials/card.html`.

    1. Open your website project in your local development environment and run the `hugo mod get github.com/CloudCannon/editable-regions` command in your terminal.
    2. Add the module to your Hugo configuration file, pinned to a version.
    3. Include the *Editable Regions* partial in the `<head>` element of your base layout.
    4. Save your changes and rebuild your *Site*.

    <comp.CodeBlock language="TOML" source="hugo.toml">
    ``````````

    [module]
      [[module.imports]]
        path = "github.com/CloudCannon/editable-regions"
        version = "<version>"

    ``````````
    </comp.CodeBlock>

    <comp.CodeBlock language="HTML" source="layouts/_default/baseof.html">
    ``````````

    {{ partial "editable-regions" . }}

    ``````````
    </comp.CodeBlock>

    <comp.Notice info_type="info">
      <p>Pinning your module to a version requires Hugo 0.150.0 or later.</p>
    </comp.Notice>

    CloudCannon rebuilds your templates in the browser from the files bundled at build time, so module imports only resolve against files inside your project. Themes in your `themes` folder are included automatically. If you use Hugo modules from the module cache, run `hugo mod vendor` so CloudCannon can resolve them.
  </comp.Tab>
  <comp.Tab name="JavaScript">
    ### JavaScript frameworks

    Sites built with React, Vue, or Svelte hydrate in the browser, which can conflict with the way CloudCannon connects *Editable Regions*. To avoid this, wrap your page content in the `EditableRegions` component, which waits for your framework to finish hydrating first.

    This applies to Next.js, Nuxt, and SvelteKit, as well as single-page applications built directly with React, Vue, or Svelte.

    <comp.Notice info_type="important">
      <p>Unlike other SSGs, sites that hydrate in the browser need this component for <em>every</em> type of <em>Editable Region</em>, not just <em>Component Editable Regions</em>.</p>
    </comp.Notice>

    1. Open your website project in your local development environment and run the `npm install @cloudcannon/editable-regions` command in your terminal.
    2. Wrap your routed page content in the `EditableRegions` component, in your root layout.
    3. Register your components from a client-side file, checking for Editor Mode first.
    4. Save your changes and rebuild your *Site*.

    <comp.CodeBlock language="JSX" source="app/layout.js">
    ``````````

    import { EditableRegions } from "@cloudcannon/editable-regions/react";

    export default function RootLayout({ children }) {
      return (
        <html lang="en">
          <body>
            <EditableRegions tag="main">{children}</EditableRegions>
          </body>
        </html>
      );
    }

    ``````````
    </comp.CodeBlock>

    Import `EditableRegions` from `@cloudcannon/editable-regions/react`, `/vue`, or `/svelte`, depending on your framework. The `tag` attribute sets which HTML element the component renders, and defaults to `div`.

    Register your components from a file that only runs in the browser, such as a client component in Next.js or a client plugin in Nuxt.

    <comp.CodeBlock language="TypeScript" source="app/plugins/cloudcannon.client.ts">
    ``````````

    import { registerVueComponent } from "@cloudcannon/editable-regions/vue";
    import CTA from "../components/CTA.vue";

    export default defineNuxtPlugin(() => {
      if (window.inEditorMode) {
        registerVueComponent('cta', CTA);
      }
    });

    ``````````
    </comp.CodeBlock>

    If you use Nuxt, you also need to tell Vue to treat the *Editable Regions* web components as standard HTML elements.

    <comp.CodeBlock language="TypeScript" source="nuxt.config.ts">
    ``````````

    export default defineNuxtConfig({
      vue: {
        compilerOptions: {
          isCustomElement: (tag) => tag.startsWith("editable-"),
        },
      },
    });

    ``````````
    </comp.CodeBlock>

    Your *Site* must output static HTML files for CloudCannon to build a preview. In Next.js, set `output: "export"` in your Next configuration file. In SvelteKit, use the static adapter and prerender every route. In Nuxt, configure Nitro to prerender your site, then build with `nuxt generate`.
  </comp.Tab>
</comp.Tabs>

## Configure a Component Editable Region

To configure *Component Editable Regions* in the [Visual Editor](/documentation/user-articles/what-is-the-visual-editor/):

1. Identify the file to which you want to add a *Component Editable Region*. We recommend any layout file that references a component and outputs to an HTML page at build time.
2. Open the file in CloudCannon's Source Editor or your local development environment.
3. Identify the component HTML element and add the HTML attribute `data-editable="component"` . If no DOM element is available, you can wrap the templating in the `<editable-component>` web component.
4. Add the `data-prop=""` HTML attribute to the same DOM element, or to the `<editable-component>` web component. The value of `data-prop` should be the path the to data property you want to edit.
5. Add the `data-component=""` HTML attribute to the same DOM element, or to the `<editable-component>` web component. The value of `data-component` should be the name of your component. In Astro, React, Svelte, and Vue, this is the name you registered it under. In Eleventy, this is the name of your include. In Hugo, this is the path of your partial.
6. Optional. If you also want to edit the text or image contents of your component in the Visual Editor, add other types of *Editable Regions* to the component layout file.
7. Save the change to your *Site*. CloudCannon will automatically rebuild your *Site*.

When you open the file in the Visual Editor, CloudCannon will show a yellow *Editable Regions* box around the component in the Visual Editor. If you added Text or *Image Editable Regions* to your component file, yellow *Editable Regions* boxes will also appear around the content.

<comp.DocShot docshot_key="CloudCannon-Documentation-Visual-Editor-Component-Editable-Region" alt="A screenshot of the Visual Editor shows a yellow Editable Region box around the Call to Action component on the blog page." title="Component Editable Region in the Visual Editor" type="screenshot"/>

When you click into the *Component Editable Region*, CloudCannon will open a data panel with inputs for all structured data keys in the component.

## Examples

Here is an example of files required for a *Component Editable Region*:

``````````

import { registerAstroComponent } from '@cloudcannon/editable-regions/astro';
import CTA from '../components/CTA.astro';

// Register your components
registerAstroComponent('cta', CTA);

``````````
</comp.CodeBlock>

``````````

title: 'First post'

  description: "Need a little more help? Send a message to our friendly support team."

``````````
</comp.CodeBlock>

``````````

---
import CTA from '../components/CTA.astro';
---

<html lang="en">
	<body>
		<main>
			<article>
                <!-- Blog HTML here -->
			</article>
			<CTA {...Astro.props.cta} /> /*1*/
		</main>
	</body>
</html>

``````````

  The `<CTA>` component uses structured data in the front matter of the files in the Blog collection.

``````````

---
const { description, link, buttonText, buttonColor } = Astro.props;
---

<p data-editable="text" data-prop="description">{description}</p>
<a href={link}>
    <button data-editable="text" data-prop="buttonText" style={`background-color: ${buttonColor}`}>{buttonText}</button>
</a>

``````````
<comp.Annotation number="1">
  This `<p>` element contains `data-editable="text"` and `data-prop="description"` to define a <comp.GlossaryTerm term="/user/glossary/t/text-editable-region.yml">Text Editable Region</comp.GlossaryTerm>.
</comp.Annotation>
<comp.Annotation number="2">
  This `<button>` element contains `data-editable="text"` and `data-prop="buttonText"` to define a *Text Editable Region*.

## Misconfigured *Component Editable Regions*

If you accidentally misconfigure your *Editable Regions*, CloudCannon will display a red warning box in the Visual Editor.

*Component Editable Regions* are misconfigured if:

* You did not define the `data-prop` or `data-component`HTML attributes.
* The *Editable Region* has an invalid data type (e.g., your Text region has a number or object, instead of a string).
* You reference a component that does not exist, or has not been registered.
* Component rendering errors
* Invalid component return values
