<comp.Notice info_type="deprecated">
  **The v0 Visual Editor API is deprecated.**

  CloudCannon continues to maintain the v0 API and fix critical bugs, but it receives no new features or further development. Existing *Sites* relying on this configuration will keep working. For new *Sites*, we recommend v1, the current version of the [Visual Editor API](/documentation/developer-articles/what-is-the-visual-editor-api/).
</comp.Notice>

Svelte re-renders a component when its reactive state changes, so a *Visual Data Preview* in Svelte comes down to assigning CloudCannon's latest data to reactive state. The connector wraps the sequence described in our documentation on [using Visual Data Previews with vanilla JavaScript](/documentation/developer-articles/visual-data-previews-with-vanilla-javascript/): it listens for CloudCannon's events, calls `enableEvents()`, reads the latest data with `value()`, and hands it to a callback you supply.

This article covers the v0 <comp.GlossaryTerm term="/user/glossary/v/visual-editor-api.yml">Visual Editor API</comp.GlossaryTerm>, not v1. The `cloudcannon:load` event belongs to both: CloudCannon dispatches it on `document` for either version, and its `detail` carries the v0 object alongside `CloudCannonAPI`, the router that v1 comes from. For the current API, please read our documentation on [what the Visual Editor API is](/documentation/developer-articles/what-is-the-visual-editor-api/).

`@cloudcannon/svelte-connector` re-exports `onCloudCannonChanges` and `stopCloudCannonChanges` from `@cloudcannon/visual-editor-connector` without changing them. Both packages behave identically, so an existing <comp.GlossaryTerm term="/user/glossary/s/site.yml">Site</comp.GlossaryTerm> importing either one keeps working.

## What your Site needs

* The component you want to preview has to render on a page CloudCannon can open. The <comp.GlossaryTerm term="/user/glossary/v/visual-editor.yml">Visual Editor</comp.GlossaryTerm> opens files, not components, and a SvelteKit route is a good example of a file that outputs to its own page.
* The component must read its data from a data or content file in your project, rather than holding it internally.
* <comp.GlossaryTerm term="/user/glossary/c/collection.yml">Collection</comp.GlossaryTerm> configuration decides whether a file has a URL the *Visual Editor* can open. For what to check, please read our documentation on [what Visual Data Previews are](/documentation/developer-articles/what-are-visual-data-previews/).
* The connector runs on the client and needs tearing down when your component goes away, which Svelte's `onMount` and `onDestroy` functions handle.

## Installation

This package targets the deprecated v0 *Visual Editor API*. For new *Sites*, please read our documentation on [initializing the Visual Editor API](/documentation/developer-articles/initialize-the-visual-editor-api/).

<comp.CodeBlock language="shell" source="Terminal">
```
npm i @cloudcannon/svelte-connector
```
</comp.CodeBlock>

## Connecting a component

Call `onCloudCannonChanges()` when your component mounts, passing a callback. The connector runs that callback on load and after every change, handing it the file's structured data, and you assign what it receives to reactive state. The code below goes inside your route's `<script>` block.

<comp.CodeBlock language="javascript" source="src/routes/+page.svelte">
```
import { onDestroy, onMount } from 'svelte';
import { onCloudCannonChanges, stopCloudCannonChanges } from '@cloudcannon/svelte-connector';

let { data } = $props(); /*1*/
let pageDetails = $state(data); /*2*/

onMount(() => {
  onCloudCannonChanges((latestValue) => {
    pageDetails = latestValue; /*3*/
  });
});

onDestroy(() => {
  stopCloudCannonChanges(); /*4*/
});
```
<comp.Annotation number="1">

Replace this line with however your route receives its data. In SvelteKit, `data` comes from the route's load function.

</comp.Annotation>
<comp.Annotation number="2">

Holds the values your markup reads. Keeping it separate from the prop means CloudCannon's updates do not fight with the data SvelteKit loaded.

</comp.Annotation>
<comp.Annotation number="3">

Assigning what the callback receives to reactive state is what updates the preview.

</comp.Annotation>
<comp.Annotation number="4">

Stops the connector listening. See the caveat below before relying on this in more than one component.

</comp.Annotation>
</comp.CodeBlock>

The example uses Svelte 5 runes. On Svelte 3 or 4, declare the prop with `export let data;` and the state with `let pageDetails = data;`. Reassignment is reactive in those versions without `$state`.

You do not need to call `enableEvents()` yourself. `onCloudCannonChanges()` does it, and also covers the case where CloudCannon has already loaded by the time your component mounts.

To cover that case, `onCloudCannonChanges()` reads `window.CloudCannon`. If other code on your page calls `useVersion('v1')`, CloudCannon reassigns that global to the v1 object, which has no `enableEvents()`, so the connector fails to start and your preview never updates. Pass `true` as the second argument, `useVersion('v1', true)`, to get the v1 object without reassigning the global. For more information, please read our documentation on [initializing the Visual Editor API](/documentation/developer-articles/initialize-the-visual-editor-api/).

## Tearing down listeners

`stopCloudCannonChanges()` removes every update listener registered through the package, not only the one belonging to the component that calls it. If two components each call `onCloudCannonChanges()`, the first to unmount stops updates for both.

Call `onCloudCannonChanges()` in one component per page, or accept that unmounting any one of them ends previews for the rest until the page reloads.
