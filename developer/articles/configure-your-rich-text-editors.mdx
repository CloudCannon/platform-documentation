You can configure your [rich text editors](/documentation/developer-articles/what-are-rich-text-editors/) to control which text and image formatting tools are available in the WYSIWYG toolbar, the upload paths or filenames for any assets uploaded through an editor, and how CloudCannon should handle custom markup.

There are multiple ways to configure your rich text editors, depending on which editor you want to configure: [the Content Editor](/documentation/user-articles/what-is-the-content-editor/), <comp.GlossaryTerm term="/user/glossary/e/editable-region.yml">Editable Regions</comp.GlossaryTerm> in the [Visual Editor](/documentation/user-articles/what-is-the-visual-editor/), or [Rich Text inputs](/documentation/user-articles/what-is-a-rich-text-input/).

For a complete list of options available for rich text editors, please read our [rich text editor reference](/documentation/developer-reference/configuration-file/types/_editables/).

## The Content Editor

To configure your *Content Editor*:

1. Navigate to your global configuration file and open it in the Source Editor. CloudCannon will show the file contents for you to edit.
2. Identify the `_editables` key, or create one at the top level of your configuration file.
3. Add the `content` key under `_editables`.
4. Add any keys you want to configure under the `content` key.
5. Save your changes to the global configuration file.

CloudCannon will offer the controls you enabled in the WYSIWYG toolbar the next time you open a file in the *Content Editor*.

Let's walk through an example. We want to allow our Organization Members to be able to apply bold, italic, and underline formatting to text in the *Content Editor*. The global configuration file should look like this:

<comp.MultiCodeBlock language="YAML" translate_into={["json"]} source="cloudcannon.config.yml">
```

_editables___1___:
  content___2___:
    bold: true
    italic: true
    underline: true

```
<comp.Annotation number="1">
  Configure the *Content Editor* and all *Editable Regions* under the `_editables` key anywhere in the [configuration cascade](/documentation/developer-articles/using-the-configuration-cascade/).
</comp.Annotation>
<comp.Annotation number="2">
  Configuration options for the *Content Editor* are nested keys under `content`. As soon as you define one key, CloudCannon will interpret any omitted keys as false and disable those options.
</comp.Annotation>
</comp.MultiCodeBlock>

## Rich Text inputs

To configure your Rich Text inputs:

1. Navigate to your global configuration file and open it in the Source Editor. CloudCannon will show the file contents for you to edit.
2. Identify the `_inputs` key, or create one at the top level of your configuration file.
3. Enter the key name for your input under the `_inputs` key.
4. Add the `options` key under your input name.
5. Add any keys you want to configure under the `options` key.
6. Save your changes to the global configuration file.

CloudCannon will offer the controls you enabled in the WYSIWYG toolbar the next time you open a file containing that input.

<comp.MultiCodeBlock language="YAML" translate_into={["json"]} source="cloudcannon.config.yml">
```

_inputs___1___:
  example___2___:
    type___3___: html
    options___4___:
      bold: true
      italic: true
      underline: true

```
<comp.Annotation number="1">
  Configure a Rich Text input under the `_inputs` key anywhere in the [configuration cascade](/documentation/developer-articles/using-the-configuration-cascade/).
</comp.Annotation>
<comp.Annotation number="2">
  Enter the key name of the input here. In this example, the input name is `example`.
</comp.Annotation>
<comp.Annotation number="3">
  This input is an HTML Rich Text input. For more information, please read our documentation on [Rich Text inputs](/documentation/user-articles/what-is-a-rich-text-input/).
</comp.Annotation>
<comp.Annotation number="4">
  Configuration options for the Rich Text inputs are nested keys under `options`.
</comp.Annotation>
</comp.MultiCodeBlock>

## Editable Regions

The `_editables` key configures *Editable Regions* as well as the *Content Editor*. CloudCannon chooses which key applies from the HTML element your region sits on:

* `text` — paragraphs, headings, blockquotes, and list items: `<p>`, `<h1>` through `<h6>`, `<blockquote>`, `<li>`, `<dd>`, and `<dt>`
* `block` — sectioning elements: `<div>`, `<section>`, `<article>`, `<aside>`, `<main>`, `<header>`, `<footer>`, and `<nav>`
* `link` — `<a>` elements
* `image` — `<img>` elements

A Text *Editable Region* can override that lookup with the `data-type` attribute, which accepts `span`, `text`, or `block`. A region with `data-type="block"` takes its configuration from `_editables.block` whichever element it sits on. For more information, please read our documentation on [configuring Text Editable Regions](/documentation/developer-articles/configure-text-editable-regions/).

To configure your *Editable Regions*:

1. Navigate to your global configuration file and open it in the Source Editor. CloudCannon will show the file contents for you to edit.
2. Identify the `_editables` key, or create one at the top level of your configuration file.
3. Add the key for the type of *Editable Region* under `_editables` (i.e., `text`, `block`, `link`, or `image`).
4. Add any keys you want to configure under the *Editable Region* key.
5. Save your changes to the global configuration file.

CloudCannon will offer the controls you enabled in the WYSIWYG toolbar the next time you open a file in the Visual Editor.

<comp.MultiCodeBlock language="YAML" translate_into={["json"]} source="cloudcannon.config.yml">
```

_editables___1___:
  text___2___:
    bold: true
    italic: true
    underline: true
  block___3___:
    format: p h3
    undo: true
    redo: true
  link___4___:
    paths:
      uploads: assets/links
  image___5___:
    mime_type: image/png
    allowed_sources:
      - site-files

```
<comp.Annotation number="1">
  Configure the *Content Editor* and all *Editable Regions* under the `_editables` key anywhere in the [configuration cascade](/documentation/developer-articles/using-the-configuration-cascade/).
</comp.Annotation>
<comp.Annotation number="2">
  Configuration options for text *Editable Regions* are nested keys under `text`.
</comp.Annotation>
<comp.Annotation number="3">
  Configuration options for block *Editable Regions* are nested keys under `block`.
</comp.Annotation>
<comp.Annotation number="4">
  Configuration options for link *Editable Regions* are nested keys under `link`. Link *Editable Regions* take upload paths only, not formatting controls.
</comp.Annotation>
<comp.Annotation number="5">
  Configuration options for image *Editable Regions* are nested keys under `image`.
</comp.Annotation>
</comp.MultiCodeBlock>

On a `class="editable"` region, you can configure options directly on the element with a JSON value in the `data-cms-options` attribute instead. *Editable Regions* defined with `data-editable` attributes do not read `data-cms-options`, and take their configuration from `_editables`.

<comp.CodeBlock language="HTML" source="page.html">
```
<p class="editable" data-cms-options='{ "bold": true, "italic": true, "underline": true}'>
  ...
</p>
```
</comp.CodeBlock>

## Text styles

The `styles` key adds a *Styles* dropdown to the WYSIWYG toolbar, offering your Organization Members a named style for each rule in a CSS file you nominate. A style is the combination of an element and a class name, so a rule such as `p.lead` becomes an option your Organization Members can apply to a paragraph. Set the value to the path of the CSS file, either in your source files or in your build output.

`styles` is available on the *Content Editor*, on text and block *Editable Regions*, and on Rich Text inputs.

<comp.DocShot docshot_key="CloudCannon-Documentation-Content-Editor-Rich-Text-Styles" alt="A screenshot of the WYSIWYG toolbar in the Content Editor shows a Styles dropdown beside the Format dropdown and the bold, italic, and underline controls." title="The Styles dropdown in the WYSIWYG toolbar" type="ui-snippet"/>

<comp.MultiCodeBlock language="YAML" translate_into={["json"]} source="cloudcannon.config.yml">
```

_editables:
  content:
    styles___1___: /css/editor.css
  text:
    styles___2___: /css/editor.css

_inputs:
  example:
    type: html
    options:
      styles___3___: /css/editor.css

```
<comp.Annotation number="1">
  Adds the *Styles* dropdown to the *Content Editor*.
</comp.Annotation>
<comp.Annotation number="2">
  Adds the *Styles* dropdown to text *Editable Regions*. A Text *Editable Region* uses this key when it sits on a `<p>`, a heading, a `<blockquote>`, or a list item, or when it sets `data-type="text"`.
</comp.Annotation>
<comp.Annotation number="3">
  Adds the *Styles* dropdown to this Rich Text input. An input that sets its own `options` uses them instead of the matching `_editables` key.
</comp.Annotation>
</comp.MultiCodeBlock>

<comp.Notice info_type="important">
  **The configuration reference does not list `styles` under `_editables.text`.**

  CloudCannon reads the key and the *Styles* dropdown appears, but the published configuration schema declares `styles` only for `_editables.content` and `_editables.block`. Your editor may flag `_editables.text.styles` as an unrecognized key.
</comp.Notice>

## Text alignment

Text alignment controls are available in the *Content Editor*, block *Editable Regions*, and Rich Text inputs. To enable them, add the `align` key to your rich text editor configuration and set each alignment you want to offer to `true`.

CloudCannon saves alignment as a `text-align` style on the block of text (e.g., `<p style="text-align: center;">`). Use the `default` key to name the alignment your CSS already applies. Selecting the default alignment in the WYSIWYG toolbar removes any existing alignment from the block rather than saving a style for it.

<comp.DocShot docshot_key="CloudCannon-Documentation-Content-Editor-Align-Text-Dropdown" alt="A screenshot of the WYSIWYG toolbar in the Content Editor shows the Align text dropdown open, offering left, center, right, and justify alignment, with left selected as the default." title="The Align text dropdown in the WYSIWYG toolbar" type="ui-snippet"/>

<comp.MultiCodeBlock language="YAML" translate_into={["json"]} source="cloudcannon.config.yml">
```

_editables:
  content:
    align___1___:
      default___2___: left
      left: true
      center: true
      right: true
      justify___3___: false

```
<comp.Annotation number="1">
  The `align` key enables the *Align text* dropdown in the WYSIWYG toolbar.
</comp.Annotation>
<comp.Annotation number="2">
  Text on this site is already left-aligned by its CSS, so selecting *Left align* clears the alignment instead of saving `text-align: left`.
</comp.Annotation>
<comp.Annotation number="3">
  Alignments set to `false` or omitted are not available in the toolbar.
</comp.Annotation>
</comp.MultiCodeBlock>

If your site aligns text with class names rather than inline styles, add them under the `classes` key. CloudCannon will toggle the class name for each alignment instead of saving a `text-align` style. Any alignment without a class name falls back to the `text-align` style. Define the class names in the CSS file you set with the `styles` key so that the alignment is visible in the editor.

<comp.MultiCodeBlock language="YAML" translate_into={["json"]} source="cloudcannon.config.yml">
```

_editables:
  content:
    styles: /css/editor.css
    align:
      default: left
      left: true
      center: true
      right: true
      classes:
        left: align-left
        center: align-center
        right: align-right

```
</comp.MultiCodeBlock>

<comp.CodeBlock language="CSS" source="css/editor.css">
```

.align-left { text-align: left; }
.align-center { text-align: center; }
.align-right { text-align: right; }

```
</comp.CodeBlock>

<comp.Notice info_type="info">
  In Markdown Rich Text inputs, CloudCannon saves aligned blocks as HTML unless your Markdown engine has `attributes: true`. With attributes enabled, CloudCannon saves alignment as a Markdown attribute (e.g., `{style="text-align: center;"}` or `{.align-center}`). For more information, please read our documentation on [configuring your Markdown engine](/documentation/developer-articles/configure-your-markdown-engine/).
</comp.Notice>

The `align` key replaces the deprecated `left`, `center`, `right`, and `justify` keys, which each took a class name. Existing configuration using those keys continues to work. To migrate, move each class name under `align.classes`, set the matching alignment to `true`, and set `default` to `left`.
