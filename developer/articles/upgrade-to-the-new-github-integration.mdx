<comp.Notice info_type="permissions">
  **Permissions required**

  Members of the *Owners* and *Developers* [Default Permission Groups](/documentation/user-articles/what-are-default-permission-groups/), or [Custom Permission Groups](/documentation/developer-articles/what-are-custom-permission-groups/) with the `org:settings:git:provider:write` permission, can upgrade an *Organization* to the new GitHub integration and switch it back.
</comp.Notice>

The new GitHub integration lets you choose which <comp.GlossaryTerm term="/user/glossary/g/git-repository.yml">Git Repositories</comp.GlossaryTerm> your <comp.GlossaryTerm term="/user/glossary/o/organization.yml">Organization</comp.GlossaryTerm> can use, instead of reaching everything one person's GitHub connection can. Your *Organization* attaches CloudCannon GitHub App installations, each with its own list of allowed *Git Repositories*. For more information, please read our documentation on [what GitHub installations are](/documentation/developer-articles/what-are-github-installations/).

When the new integration is available to your *Organization*, the *GitHub* page under the *Files* heading in your <comp.GlossaryTerm term="/user/glossary/o/org-settings.yml">Org Settings</comp.GlossaryTerm> shows a *New GitHub integration available* notice below the page heading, above the tabs. For *Sites* that sync with GitHub, the *Syncing* page under *Site Settings* shows the same notice below its page heading. Only members who can upgrade the *Organization* see the notice. If your *Organization* already uses the CloudCannon GitHub App, upgrading changes nothing on GitHub. You can switch back to the previous integration for 30 days.

## Upgrade an Organization that uses the GitHub App

If your *Organization* already authorized GitHub through the CloudCannon GitHub App, the upgrade modal lists the installations your *Organization's* GitHub connection can reach. Installations that your <comp.GlossaryTerm term="/user/glossary/s/site.yml">Sites</comp.GlossaryTerm> use start with all of their *Git Repositories* allowed, and installations no *Site* uses start with no access. If your *Organization* switched back from the new integration, each installation it kept starts with the *Git Repositories* it allowed before. The upgrade attaches each installation that has access, so by default the ones your *Sites* use, and detaches any kept installation you set to *No access*. You can change what any installation serves before you upgrade. If your *Organization's* GitHub connection has expired, the modal shows an error that reads *Reconnect GitHub for this Organization first*, with a *Reconnect GitHub* button that takes you to GitHub to renew the connection.

During the upgrade, the *Choose repositories from [Account Name]* modal lists the *Git Repositories* through your *Organization's* GitHub connection, so you do not need GitHub connected to your own account. After you upgrade, adding *Git Repositories* to an installation uses the GitHub connection on your own account.

To upgrade:

1. Click the *Org Settings* link in the <comp.GlossaryTerm term="/user/glossary/a/app-sidebar.yml">App Sidebar</comp.GlossaryTerm>. CloudCannon will open the *Details* page.
2. Navigate to the *GitHub* page under the *Files* heading. CloudCannon will open the *Authorization* tab.
3. Click the *Upgrade GitHub integration* button in the *New GitHub integration available* notice. CloudCannon will open the *Upgrade to the new GitHub integration* modal, which lists each installation on a *Card* under the *Attached when you upgrade* or *Not attached* heading, showing whether it serves all, some, or none of its *Git Repositories*, and which *Sites* use it.
4. To change what an installation serves, click the *Edit* button on its *Card*. CloudCannon will open the *Choose repositories from [Account Name]* modal.
5. Select the *All repositories* option, the *Only selected repositories* option, or the *No access* option.
6. If you selected the *Only selected repositories* option, search for each *Git Repository* in the *Repositories* field and select it.
7. Click the *Save repositories* button, the *Attach with all repositories* button, the *Attach with [Number] repositories* button, the *Remove access* button, or the *Don't attach* button. CloudCannon will close the modal and update the installation's *Card*.
8. Click the *Upgrade integration* button.

CloudCannon will attach the installations, switch your *Organization* to the new integration, and open the *Installations* tab with a *This Organization now uses the new GitHub integration* notice above the tabs. CloudCannon will also email the members of your *Organization's* *Owners Permission Group* that the upgrade is complete, with a link to the *Installations* tab and a reminder that you can switch back for 30 days.

The confirming button in the *Choose repositories from [Account Name]* modal reads *Save repositories* for an installation that already has access, *Attach with all repositories* or *Attach with [Number] repositories* for one that starts with no access, and *Remove access* or *Don't attach* when you select the *No access* option.

If a *Site* uses a *Git Repository* that no installation will serve, both the *Upgrade to the new GitHub integration* modal and the *Choose repositories from [Account Name]* modal show a warning naming the *Git Repository* and its *Sites*. Click the *Add it* button or the *Add them all* button in the warning to allow them. A *Git Repository* that the CloudCannon GitHub App cannot reach cannot be added here. In the *Choose repositories from [Account Name]* modal, when the warning lists a *Git Repository* the CloudCannon GitHub App cannot reach, it has a *Configure on GitHub* button that opens the installation's settings on GitHub.

## Upgrade an Organization that uses the older GitHub authorization

If your *Organization* authorized GitHub before the CloudCannon GitHub App existed, the CloudCannon GitHub App is not installed on the GitHub accounts your *Sites* use yet. The upgrade takes you to GitHub to install it.

Installing needs GitHub connected to your account. If the modal shows a *Connect GitHub* button instead of the *Install on GitHub* button, click the *Connect GitHub* button and authorize CloudCannon on GitHub. CloudCannon will return you to the *GitHub* page, where you click the *Upgrade GitHub integration* button again.

To upgrade:

1. Click the *Org Settings* link in the *App Sidebar*. CloudCannon will open the *Details* page.
2. Navigate to the *GitHub* page under the *Files* heading. CloudCannon will open the *Authorization* tab.
3. Click the *Upgrade GitHub integration* button in the *New GitHub integration available* notice. CloudCannon will open the *Upgrade to the new GitHub integration* modal, which lists the GitHub accounts your *Sites* use under the *Accounts to install on* heading.
4. Click the *Install on GitHub* button. CloudCannon will switch your *Organization* to the new integration and send you to GitHub.
5. Follow the prompts on GitHub to install the CloudCannon GitHub App on the account your *Sites* use.

GitHub will return you to the *Installations* tab. CloudCannon will attach the installation with the repository access you chose on GitHub and open the *Choose repositories from [Account Name]* modal for it; click the *Save repositories* button to keep those *Git Repositories*. If you started from the *Syncing* page under *Site Settings*, GitHub returns you there instead, and you change the repositories from the *Installations* tab. CloudCannon will also email the members of your *Organization's* *Owners Permission Group* that the upgrade is complete, with a link to the *Installations* tab and a reminder that you can switch back for 30 days. *Sites* on an account without the CloudCannon GitHub App stop syncing until you install it there and attach it. To install it on another account, please read our documentation on [attaching a GitHub installation](/documentation/developer-articles/attach-a-github-installation/).

## Switch back to the previous integration

For 30 days after upgrading, the *This Organization now uses the new GitHub integration* notice on the *GitHub* page under *Org Settings* shows the date until which you can switch back, with a *Switch back* button. Switching back returns your *Organization* to syncing through the GitHub connection it used before, which reaches every *Git Repository* that account can. The installations and their lists of *Git Repositories* are kept, so upgrading again restores them.

To switch back:

1. Navigate to the *GitHub* page under the *Files* heading in your *Org Settings*. CloudCannon will open the *Installations* tab.
2. Click the *Switch back* button in the *This Organization now uses the new GitHub integration* notice. CloudCannon will open the *Switch back to the previous GitHub integration?* modal.
3. Click the *Switch back* button.

CloudCannon will switch your *Organization* back to the previous integration and open the *Authorization* tab, with the *New GitHub integration available* notice shown again. After 30 days, the notice and the *Switch back* button are no longer shown.
