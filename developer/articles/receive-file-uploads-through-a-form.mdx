A <comp.GlossaryTerm term="/user/glossary/f/form.yml">Form</comp.GlossaryTerm> can accept file uploads from visitors alongside its other fields, and CloudCannon stores the files with the submission.

To accept file uploads through a *Form*:

1. Set your form's `enctype` attribute to `multipart/form-data`.
2. Add an input to your form with its `type` attribute set to `file`.

<comp.CodeBlock language="html" source="upload.html">
```
<form action="/" enctype="multipart/form-data" method="post">
  <input accept="image/png, image/jpeg" id="avatar" name="avatar" type="file">
  <input type="submit" value="Send Message">
</form>
```
</comp.CodeBlock>

When a visitor submits a file, CloudCannon saves it and replaces it in the submission with a link you can use to reach it. Opening that link requires a CloudCannon login, so a target's notification email is not enough on its own to reach an attached file.

If you want <comp.GlossaryTerm term="/user/glossary/c/client-sharing.yml">Client Sharing</comp.GlossaryTerm> users to open attachments, they have to log in through the Client Login Page. For how to point a target's notifications there, please read our documentation on [what an Inbox Target is](/documentation/developer-articles/what-is-an-inbox-target/).

## File upload limits

These limits apply to every submission that carries a file:

* Each file must be smaller than 5 MB.
* At most five files can be submitted at a time.
* Each non-file field must be smaller than 10 KB.
* At most 100 non-file fields can be submitted at a time.

A submission that exceeds one of these limits is rejected rather than truncated. For the separate limits on how many submissions an <comp.GlossaryTerm term="/user/glossary/i/inbox.yml">Inbox</comp.GlossaryTerm> accepts, please read our documentation on [how Inbox limits work](/documentation/developer-articles/how-do-inbox-limits-work/).
