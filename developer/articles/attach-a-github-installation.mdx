<comp.Notice info_type="permissions">
  **Permissions required**

  Members of the *Owners* and *Developers* [Default Permission Groups](/documentation/user-articles/what-are-default-permission-groups/), or [Custom Permission Groups](/documentation/developer-articles/what-are-custom-permission-groups/) with the `org:settings:git:provider:write` permission, can attach, edit, and detach GitHub installations. Attaching an installation or adding repositories also needs a GitHub connection on your account that can reach the installation.
</comp.Notice>

A GitHub installation is the CloudCannon GitHub App installed on one GitHub organization or personal account. Attaching an installation to your <comp.GlossaryTerm term="/user/glossary/o/organization.yml">Organization</comp.GlossaryTerm> lets your <comp.GlossaryTerm term="/user/glossary/s/site.yml">Sites</comp.GlossaryTerm> use the <comp.GlossaryTerm term="/user/glossary/g/git-repository.yml">Git Repositories</comp.GlossaryTerm> you allow on that account. For more information, please read our documentation on [what GitHub installations are](/documentation/developer-articles/what-are-github-installations/).

Before we begin, this article assumes your *Organization* uses the new GitHub integration, and that GitHub is connected to your account on the *OAuth Providers* page under *Account Settings*. CloudCannon uses your GitHub connection to find the installations you can attach. To move your *Organization* to the new integration, please read our documentation on [upgrading to the new GitHub integration](/documentation/developer-articles/upgrade-to-the-new-github-integration/).

## Attach an installation

The *Attach an installation* modal lists the GitHub accounts your *Sites* use, and the accounts with the CloudCannon GitHub App installed that your GitHub connection can reach. It groups them under the *Attached to this Organization* and *Not attached* headings, and lists the accounts your *Sites* need first in each.

To attach an installation:

1. Click the <comp.GlossaryTerm term="/user/glossary/o/org-settings.yml">Org Settings</comp.GlossaryTerm> link in the <comp.GlossaryTerm term="/user/glossary/a/app-sidebar.yml">App Sidebar</comp.GlossaryTerm>. CloudCannon will open the *Details* page.
2. Navigate to the *GitHub* page under the *Files* heading. CloudCannon will open the *Installations* tab.
3. Click the *Attach installation* button. CloudCannon will open the *Attach an installation* modal.
4. Click the *Attach* button on the account you want. CloudCannon will open the *Choose repositories from [Account Name]* modal.
5. Select the *All repositories* option or the *Only selected repositories* option.
6. If you selected the *Only selected repositories* option, search for each *Git Repository* in the *Repositories* field and select it.
7. Click the *Attach with all repositories* button or the *Attach with [Number] repositories* button.

CloudCannon will attach the installation and list it on the *Installations* tab. Your *Sites* can now use the *Git Repositories* you allowed, and they appear in the *Repository* dropdown when you create a *Site* or connect one to GitHub.

Whether you are attaching an installation or changing its *Git Repositories*, the *Choose repositories from [Account Name]* modal does not show the *All repositories* option when your GitHub account cannot reach every *Git Repository* the installation can, unless the installation already serves all repositories, in which case you can narrow it to any of them. Otherwise, select the *Only selected repositories* option and add the *Git Repositories* your GitHub account can reach. If a *Git Repository* is missing from the *Repositories* field, either the CloudCannon GitHub App cannot reach it on GitHub, or your GitHub account cannot reach it. For an attached installation, the *Can I edit this?* option in the *Context Menu* on its *Card* opens the *Your access to [Account Name]* modal, which shows whether your GitHub account can reach the installation at all. Click the *Give the installation access to it on GitHub* link at the top of the modal to change the installation's access on GitHub.

If the account you want is not listed, the CloudCannon GitHub App is not installed on it, or your GitHub account cannot reach it. If the CloudCannon GitHub App is already installed there, the account appears once your GitHub account can reach one of its *Git Repositories*. Otherwise, click the *Configure another GitHub installation* button (or the *Install on GitHub* button, if no account is listed at all) to install the CloudCannon GitHub App on GitHub. When GitHub returns you to the *Installations* tab, the installation is attached to your *Organization* with the repository access you chose on GitHub (or, for an account that showed *Removed on GitHub*, the *Git Repositories* it allowed before), and CloudCannon opens the *Choose repositories from [Account Name]* modal so you can change it. If GitHub is not connected to your account, or your connection needs renewing, the modal shows a *Connect GitHub* button.

## Change which repositories an installation serves

Removing a *Git Repository* from an installation needs no GitHub connection. Adding one needs a GitHub connection on your account that can reach it, unless the installation already serves all repositories, in which case you can narrow it to any of them. If your GitHub account cannot reach the installation, the modal lists the allowed *Git Repositories* with *Remove* buttons and explains that you can only remove them.

To change which *Git Repositories* an installation serves:

1. Navigate to the *GitHub* page under the *Files* heading in your *Org Settings*. CloudCannon will open the *Installations* tab.
2. Open the *Context Menu* on the installation's *Card*. CloudCannon will open the *Context Menu* with the *Edit repositories*, *Configure on GitHub*, *Can I edit this?*, and *Detach* options.
3. Select the *Edit repositories* option. CloudCannon will open the *Choose repositories from [Account Name]* modal.
4. Select the *All repositories* option or the *Only selected repositories* option.
5. If you selected the *Only selected repositories* option, add or remove *Git Repositories* in the *Repositories* field.
6. Click the *Save repositories* button.

CloudCannon will save the allowed *Git Repositories* and reload the *Installations* tab. A *Site* on a *Git Repository* you removed stops syncing on its next sync until you add the *Git Repository* back.

<comp.DocShot docshot_key="CloudCannon-Documentation-Org-GitHub-V3-Edit-Repositories-Modal" alt="A screenshot of the Choose repositories from acme modal shows the Only selected repositories option selected, four allowed repositories, and a warning that Sites on acme/handbook cannot sync until it is on the list, with an Add it button." title="The Choose repositories from [Account Name] modal with a warning" type="screenshot"/>

If a *Site* syncs with a *Git Repository* that is not on the list, the modal shows a warning naming the *Git Repository* and its *Sites*. Click the *Add it* button or the *Add them all* button in the warning to add them. If the CloudCannon GitHub App cannot reach one of those *Git Repositories*, the warning says so, and the *Configure on GitHub* button in the warning opens the installation's settings on GitHub.

## Fix Sites that cannot sync

When a *Site* syncs with a *Git Repository* that its installation does not serve, the *Installations* tab shows a warning that reads *[Number] Sites cannot sync until the GitHub installations they use are attached and allow their repositories*. For the reasons a *Site* cannot sync, please read our documentation on [what GitHub installations are](/documentation/developer-articles/what-are-github-installations/#sites-that-cannot-sync).

To give those *Sites* access:

1. Navigate to the *GitHub* page under the *Files* heading in your *Org Settings*. CloudCannon will open the *Installations* tab.
2. Click the *Attach installations* button in the warning. CloudCannon will open the *Attach an installation* modal, with the accounts your *Sites* need listed first under each heading.
3. Click the *Attach* button, the *Attach again* button, or the *Edit repositories* button on the account. CloudCannon will open the *Choose repositories from [Account Name]* modal.
4. Choose the *Git Repositories* the installation serves, making sure the *Git Repositories* named in the warning are on the list.
5. Click the *Attach with all repositories* button, the *Attach with [Number] repositories* button, or the *Save repositories* button.

CloudCannon will attach or update the installation, and the *Sites* will sync again on their next sync. An account that shows *Suspended on GitHub* has a *Configure on GitHub* button instead, which opens the installation's settings on GitHub so you can unsuspend it. An account that shows *Removed on GitHub* and is not installed has an *Install on [Account Name]* button, which takes you to GitHub to install the CloudCannon GitHub App again.

<comp.DocShot docshot_key="CloudCannon-Documentation-Org-GitHub-V3-Attach-Needed-Modal" alt="A screenshot of the Attach an installation modal lists acme with an Edit repositories button because two Sites need repositories added, northwind with an Attach button because three Sites need it, and bigcorp with an Install on bigcorp button." title="The Attach an installation modal with accounts that Sites need" type="screenshot"/>

You can also start from the *Site*. The *Syncing* page under *Site Settings* shows a notice that reads *This Site stops syncing on its next sync*, with an *Attach [Account Name]*, *Attach again*, *Edit repositories*, or *Configure on GitHub* button for the fix.

## Detach an installation

Detaching an installation removes it from your *Organization*. Nothing changes on GitHub, and *Sites* on its *Git Repositories* stop syncing until it is attached again. The person who attached an installation can also detach it from the *OAuth Providers* page under *Account Settings*.

To detach an installation:

1. Navigate to the *GitHub* page under the *Files* heading in your *Org Settings*. CloudCannon will open the *Installations* tab.
2. Open the *Context Menu* on the installation's *Card*. CloudCannon will open the *Context Menu* with the *Edit repositories*, *Configure on GitHub*, *Can I edit this?*, and *Detach* options.
3. Select the *Detach* option. CloudCannon will open the *Detach [Account Name]?* modal, which names the *Sites* that stop syncing.
4. Click the *Detach installation* button.

CloudCannon will detach the installation and reload the *Installations* tab.

<comp.DocShot docshot_key="CloudCannon-Documentation-Org-GitHub-V3-Detach-Modal" alt="A screenshot of the Detach acme? modal says that five Sites stop syncing until acme is attached again and that nothing changes on GitHub, with Cancel and Detach installation buttons." title="The Detach [Account Name]? modal" type="screenshot"/>

Selecting the *No access* option in the *Choose repositories from [Account Name]* modal and clicking the *Remove access* button detaches the installation in the same way.

## Change what an installation can reach on GitHub

CloudCannon can only allow *Git Repositories* that the CloudCannon GitHub App can reach on GitHub. To give the installation access to more *Git Repositories*, or to remove its access, open the *Context Menu* on the installation's *Card* and select the *Configure on GitHub* option. GitHub will open the installation's settings, where you choose between all repositories and selected repositories for the account. GitHub installation settings also let you suspend or uninstall the CloudCannon GitHub App. A suspended or uninstalled installation stops every *Site* that uses it from syncing, in every *Organization* it is attached to.
