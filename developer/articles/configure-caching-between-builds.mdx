<comp.Notice info_type="permissions">
  **Permissions required**

  Members of the *Owners*, *Developers*, and *Partner* [Default Permission Groups](/documentation/user-articles/what-are-default-permission-groups/), or [Custom Permission Groups](/documentation/developer-articles/what-are-custom-permission-groups/) with the `site:settings:build:write` permission, can change the caching options for a *Site*.
</comp.Notice>

CloudCannon lets you choose certain files and folders to cache between builds of your <comp.GlossaryTerm term="/user/glossary/s/site.yml">Site</comp.GlossaryTerm>. Caching files can let you skip install steps, which speeds up later builds.

## Preserved paths

The *Preserved Paths* field lets you set a comma-separated list of path prefixes that should not be deleted in subsequent builds. A path prefix can be a folder or a full filename.

Be careful caching files, as this could result in files sticking around after deleting them from your *Git Repository*. A good rule is that these paths should also be good examples of paths for your `.gitignore` file.

If you are doing any image processing or plugin-level caching, specify that directory, or the full filename. A specific example would be caching your `node_modules/` directory, which would allow `npm install` commands to run more quickly on subsequent builds.

To update your preserved paths:

1. Navigate to the *Build configuration* page under *Site Settings*.
2. Click the *Caching options* card. CloudCannon will expand the card to show the *Preserved Paths* field and the *Preserve Output* checkbox.
3. Enter a comma-separated list of path prefixes you want to preserve between builds in the *Preserved Paths* field.
4. Click the *Update Configuration and Build* button. CloudCannon will save your build configuration and start a build.

CloudCannon will save the files that match your *Preserved Paths* after each successful build, and restore them before the next build of your *Site*.

If builds are locked on your *Site*, the button reads *Update Configuration*.

<comp.Notice info_type="info">
  If a build is interrupted before it finishes, CloudCannon will start the next build without your preserved paths, so files left behind by the interrupted build cannot affect it.
</comp.Notice>

## Preserve output

*Preserve Output* lets you cache the files in your <comp.GlossaryTerm term="/user/glossary/o/output.yml">output</comp.GlossaryTerm> directory between builds. Your output directory is the folder set in the *Output Path* field on the *Build configuration* page.

To preserve your output:

1. Navigate to the *Build configuration* page under *Site Settings*.
2. Click the *Caching options* card. CloudCannon will expand the card to show the *Preserved Paths* field and the *Preserve Output* checkbox.
3. Select the *Preserve Output* checkbox.
4. Click the *Update Configuration and Build* button. CloudCannon will save your build configuration and start a build.

CloudCannon will cache the files in your output directory between builds of your *Site*.

If builds are locked on your *Site*, the button reads *Update Configuration*.

## Preserved paths in your build log

When your *Site* has *Preserved Paths* set, your build log shows whether CloudCannon restored your preserved paths before the build and whether it saved them afterward. These lines appear in the main build only, not in post-processing or other build steps. A *Site* without *Preserved Paths* set shows none of these lines.

For where to find your build logs, please read our documentation on [what a Site build is](/documentation/developer-articles/what-is-a-site-build/).

### Before the build

When your *Site* has *Preserved Paths* set, your build log shows one of these lines before the build, under `$ cloudcannon files pull` and just before the line that starts `Syncing`:

* `Downloading preserved paths from cache... done` — CloudCannon restored your preserved paths from the cache.
* `Preserved paths up to date` — your preserved paths were already in place from the previous build, so CloudCannon had nothing to download.
* `Restoring preserved files failed` — CloudCannon could not restore your preserved paths, and the build continued without them. This line appears in red.

If none of these lines appears, the build started without your preserved paths, and your build had to recreate those files. The build log does not show a separate line for this. It happens:

* On the first build of a *Site*, or the first build after you set *Preserved Paths*.
* On the build after an interrupted build, which starts without your preserved paths on purpose.
* After a build that saved no files, which shows `Removing preserved paths cache... done`.
* When CloudCannon has removed the cache for a *Site* that has not built for a long time.

### After the build

When your *Site* has *Preserved Paths* set, your build log shows one of these lines after a successful build, under `$ cloudcannon files push` and before the line that starts `Uploading files`:

* `Writing preserved paths to cache... done` — your preserved paths changed since CloudCannon last saved them, or there was no cache yet, so CloudCannon saved them.
* `Preserved paths unchanged` — your preserved paths are the same as last time, so CloudCannon saved nothing.
* `Removing preserved paths cache... done` — no files matched your *Preserved Paths* after the build, so CloudCannon deleted the cache. The next build will start without preserved paths.
* `Saving preserved files failed` — CloudCannon could not save your preserved paths, but the build still succeeded. This line appears in red.

A failed build saves nothing and shows none of these lines. The next build will restore your preserved paths from the last successful build.

### Repeated cache failures

If `Restoring preserved files failed` or `Saving preserved files failed` appears in your build log for several builds in a row, contact <a href="https://cloudcannon.com/support/">CloudCannon support</a>. Have your *Site* name, the date and time of the affected builds, and the failed line from your build log ready.

## Caching gem installs

Installing your gems can add time to every build.

To save time on consecutive builds, CloudCannon does the following:

1. Installs your gems to a local folder
2. Caches that folder based on your `Gemfile.lock`
3. When no local gems are found, CloudCannon will build your *Site* using the cached installs from your previous build
