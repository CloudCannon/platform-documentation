<comp.Notice info_type="permissions">
  <p><strong>Permissions required</strong></p><p>Members of the <em>Owners</em>, <em>Developers</em>, <em>Technical Editors</em>, and <em>Partner</em> <a href="/documentation/user-articles/what-are-default-permission-groups/">Default Permission Groups</a>, or <a href="/documentation/developer-articles/what-are-custom-permission-groups/">Custom Permission Groups</a> with the <code>site:source-editor:write</code> permission, can add <em>Editable Regions</em> to files using the <em>Source Editor</em> in CloudCannon.</p>
</comp.Notice>

<comp.GlossaryTerm term="/user/glossary/a/array-editable-region.yml">Array Editable Regions</comp.GlossaryTerm> and <comp.GlossaryTerm term="/user/glossary/a/array-item-editable-region.yml">Array Item Editable Regions</comp.GlossaryTerm> are two types of [Editable Region](/documentation/developer-articles/what-are-editable-regions/) you can add to your layout and HTML-like files to enable visual editing. *Array Editable Regions* allow you to add, remove, and reorder array values stored in structured data or front matter that populate templating in layout files. You can use *Array Editable Regions* to edit array components or support page building in the <em>Visual Editor</em>.

<comp.Notice info_type="info">
  <p>To avoid misconfiguration issues where CloudCannon cannot find the data property you want to edit, always add <em>Editable Regions</em> to values closest to the root of the file first (i.e., work from parent elements towards child elements).</p>
</comp.Notice>

*Array Editable Regions* support two kinds of array. In a simple array, every array item has the same structure, such as a list of testimonials that each have an image, a name, and a quote. In a complex array, array items have different structures, such as a list of page-building blocks where each array item is a different component.

These instructions assume you have configured your [build settings](/documentation/developer-articles/configure-your-first-build/) and are comfortable editing HTML layouts, either in CloudCannon's [Source Editor](/documentation/user-articles/what-is-the-source-editor/) or your local development environment.

If you have a complex array, you also need to install the *Editable Regions* integration for your SSG and register each type of array item as a component before you begin. CloudCannon provides this integration for Astro, Eleventy, and Hugo, and a root component for sites built with React, Vue, or Svelte, including Next.js, Nuxt, and SvelteKit. For more information, please read our documentation on [configuring Component Editable Regions](/documentation/developer-articles/configure-component-editable-regions/).

To configure *Array Editable Regions* in the [Visual Editor](/documentation/user-articles/what-is-the-visual-editor/):

1. Identify the file to which you want to add an *Array Editable Region*.
2. Open the file in CloudCannon's *Source Editor* or your local development environment.
3. Identify the templating responsible for looping over your array and add the `data-editable="array"` HTML attribute to the element that wraps it. If no appropriate tags are available, wrap the templating in the `<editable-array>` web component.
4. Add the `data-prop=""` HTML attribute to the same DOM element, or to the `<editable-array>` web component. The value of `data-prop` should be the path to the data property you want to edit.
5. If you have a complex array, you must add the `data-id-key` HTML attribute to the same DOM element, or to the `<editable-array>` web component. The value of `data-id-key` should be the structured data key that stores the unique identifier of each array item (e.g., `_name`).
6. If you have a complex array, you must add the `data-component-key` HTML attribute to the same DOM element, or to the `<editable-array>` web component. The value of `data-component-key` should be the structured data key that stores the name of your component (e.g., `_name`).
7. Identify the HTML element within your array templating that contains your array item and add the `data-editable="array-item"` HTML attribute. If no appropriate tags are available, wrap the content of the array item in the `<editable-array-item>` web component.
8. If you have a complex array, you must add the `data-id` HTML attribute to the same DOM element, or to the `<editable-array-item>` web component. The value of `data-id` should be a templating that will populate with the value of the `data-id-key` key (e.g., `{block._name}`).
9. If you have a complex array, you must add the `data-component` HTML attribute to the same DOM element, or to the `<editable-array-item>` web component. The value of `data-component` should be a templating that will populate with the value of the `data-component-key` key (e.g., `{block._name}`).
10. Save your changes and rebuild your *Site*.

When you open the file in the *Visual Editor*, CloudCannon will show yellow *Editable Region* boxes around each array item, and around any *Editable Regions* inside them.

<comp.DocShot docshot_key="CloudCannon-Documentation-Visual-Editor-Simple-Array-Editable-Region" alt="A screenshot of the Visual Editor shows yellow Editable Region boxes around each array item on the Quotes webpage, and around the image, name, job title, and quote inside each item." title="Array Editable Regions in the Visual Editor" type="screenshot"/>

When you hover over an array item, CloudCannon will show a small toolbar in the top right of the array item, containing an edit icon and a drag handle icon. Clicking the edit icon opens a *Data Panel* containing the fields for that array item. Clicking the drag handle icon opens the *Context Menu*, with options to add, duplicate, move, and delete the array item. Clicking and holding the drag handle icon allows you to drag the array item to any position in the array.


<comp.Notice info_type="info">
  <p><strong>Where should the Array and Array Item </strong><em><strong>Editable Regions</strong></em> <strong>go?</strong></p><p>We recommend placing the Array attribute or web component on the element that wraps your array templating, and the Array Item attribute or web component on the first element inside each loop iteration. This way, Array and Array Item flank the templating for looping over your array.</p><p>Other HTML elements can sit between the Array and Array Item <em>Editable Regions</em>, but another <em>Editable Region</em> cannot. CloudCannon matches each Array Item <em>Editable Region</em> to its nearest parent <em>Editable Region</em>, and shows an error if that parent is not an <em>Array Editable Region</em>.</p>
</comp.Notice>

If you also want to edit the contents of each array item in the *Visual Editor*, you can add [Text Editable Regions](/documentation/developer-articles/configure-text-editable-regions/) or [Image Editable Regions](/documentation/developer-articles/configure-image-editable-regions/) to the content inside each array item.

In the `TestimonialsLayout.astro` layout file, the `<ul>` element wraps the loop over the `testimonials` array, so it is the *Array Editable Region*. Each `<li>` element is an *Array Item Editable Region*. Inside each array item, *Image* and *Text Editable Regions* let your team edit the image, name, job title, and quote.

<comp.CodeBlock language="Astro" source="TestimonialsLayout.astro">
``````````

---
const { testimonials } = Astro.props.frontmatter;
---

<!doctype html>
<html lang="en">
  <body>
    <main>
      <section>
        <ul data-editable="array" data-prop="testimonials"> /*1*/
          {
            testimonials.map((testimonial) => (
              <li data-editable="array-item" >
                {testimonial.image && (
                  <img
                    data-editable="image"
                    data-prop-src="image"
                    data-prop-alt="image_alt"
                    width={720}
                    height={360}
                    src={testimonial.image}
                    alt={testimonial.image_alt}
                  /> /*2*/
                )}
                <h4 class="name" data-editable="text" data-prop="name">{testimonial.name}</h4> /*3*/
                <p class="job" data-editable="text" data-prop="job_title">{testimonial.job_title}</p> /*4*/
                <p class="quote" data-editable="text" data-prop="quote">{testimonial.quote}</p> /*5*/
              </li>
            ))
          }
        </ul>
      </section>
    </main>
  </body>
</html>

``````````
<comp.Annotation number="1">

  The `data-editable` attribute defines what kind of data this element contains, and the `data-prop` attribute defines the path to the data we want to edit. In this case, we want an *Array Editable Region*, so the value of `data-editable` is `array`, and we want to edit the `testimonials` structured data key in the file front matter.

</comp.Annotation>
<comp.Annotation number="2">

  This `<img>` element contains `data-editable="image"`, `data-prop-src="image"`, and `data-prop-alt="image_alt"` to define an *Image Editable Region*.

</comp.Annotation>
<comp.Annotation number="3">

  This `<h4>` element contains `data-editable="text"` and `data-prop="name"` to define a *Text Editable Region*.

</comp.Annotation>
<comp.Annotation number="4">

  This `<p>` element contains `data-editable="text"` and `data-prop="job_title"` to define a *Text Editable Region*.

</comp.Annotation>
<comp.Annotation number="5">

  This `<p>` element contains `data-editable="text"` and `data-prop="quote"` to define a *Text Editable Region*.

</comp.Annotation>
</comp.CodeBlock>

In this example of a complex array, the `about.md` file contains array items with different structures. Each content block is rendered by a different component, so the registration script registers each component under the same name stored in the `_name` key.

<comp.CodeBlock language="JavaScript" source="src/scripts/register-components.js">
``````````

import { registerAstroComponent } from '@cloudcannon/editable-regions/astro';
import '@cloudcannon/editable-regions/astro-react-renderer'; /*1*/
import HeroBlock from '../components/HeroBlock.astro';
import StatsBlock from '../components/StatsBlock.astro';
import ContactBlock from '../components/ContactBlock.astro';

// Register your components
registerAstroComponent('HeroBlock', HeroBlock);
registerAstroComponent('StatsBlock', StatsBlock);
registerAstroComponent('ContactBlock', ContactBlock);

``````````
<comp.Annotation number="1">

  This import is only necessary if you use React components nested inside your Astro components.

</comp.Annotation>
</comp.CodeBlock>

In the `AboutLayout.astro` layout file, the `<main>` element is the *Array Editable Region*. Its `data-id-key` and `data-component-key` HTML attributes both point to the `_name` key, which stores the unique identifier of each content block and the name of its registered component. Each `<section>` element is an *Array Item Editable Region*, with `data-id` and `data-component` HTML attributes that populate with the value of `_name` at build time.

<comp.CodeBlock language="Astro" source="AboutLayout.astro">
``````````

---
const components = {};
const componentImports = import.meta.glob("../components/**/*.astro", {
  eager: true,
});
Object.entries(componentImports).forEach(([path, obj]) => {
  const name = path.replace("../components/", "").split(".")[0];
  components[name] = obj.default;
});

const { contentBlocks } = Astro.props.frontmatter;
---

<main data-editable="array" data-prop="contentBlocks" data-id-key="_name" data-component-key="_name"> /*1*/
  {
    contentBlocks.map((block) => {
      const Component = components[block._name];
      return (
        <section data-editable="array-item" data-id={block._name} data-component={block._name}> /*2*/
          <Component {...block} />
        </section>
      );
    })
  }
</main>

``````````
<comp.Annotation number="1">

  The `data-id-key` and `data-component-key` attributes tell CloudCannon to read the identifier and component name of each array item from the `_name` key.

</comp.Annotation>
<comp.Annotation number="2">

  The `data-id` and `data-component` attributes populate with the value of `_name` for each array item at build time (e.g., `HeroBlock`).

</comp.Annotation>
</comp.CodeBlock>

## Render new array items

When you add an array item in the *Visual Editor*, CloudCannon needs markup to display the new array item before your *Site* rebuilds. CloudCannon uses the first of the following that your *Array Editable Region* provides:

* A `<template>` element inside your *Array Editable Region*. A `<template>` element without a `data-id` HTML attribute is the markup for every new array item. To use different markup for each type of array item, add a `data-id` HTML attribute to each `<template>` element, matching a value of the key named by `data-id-key`. If a `<template>` element contains more than one root element, CloudCannon wraps its contents in an `<editable-array-item>` web component. CloudCannon adds `data-editable="array-item"` to the root element of each new array item, so you don't need to include it in your `<template>` element.
* A registered component, named by the `data-component-key` HTML attribute for each array item, or by the `data-component` HTML attribute on the *Array Editable Region* as a fallback for every array item.
* A copy of an existing array item. For a complex array, CloudCannon only copies an existing array item with the same `data-id`.

In this example, the `<template>` element gives CloudCannon the markup for new testimonials, so your team can add a testimonial even when the array is empty.

<comp.CodeBlock language="Astro" source="TestimonialsLayout.astro">
``````````

<ul data-editable="array" data-prop="testimonials">
  <template>
    <li data-editable="array-item">
      <h4 class="name" data-editable="text" data-prop="name"></h4>
      <p class="quote" data-editable="text" data-prop="quote"></p>
    </li>
  </template>
  {
    testimonials.map((testimonial) => (
      <li data-editable="array-item">
        <h4 class="name" data-editable="text" data-prop="name">{testimonial.name}</h4>
        <p class="quote" data-editable="text" data-prop="quote">{testimonial.quote}</p>
      </li>
    ))
  }
</ul>

``````````
</comp.CodeBlock>

For more information about `<template>`, `data-component`, and `data-component-key`, please read our documentation on [Editable Region HTML attributes](/documentation/developer-reference/editable-regions/).

## Match the direction of your array

The array item controls in the *Visual Editor* follow the direction of your array. For a vertical array, the *Context Menu* shows *Move up* and *Move down* options, and for a horizontal array it shows *Move left* and *Move right* options. CloudCannon also uses the direction to show where an array item will land when you drag it.

To set the direction, add the `data-direction` HTML attribute to your *Array Editable Region*, with a value of `row`, `column`, `row-reverse`, or `column-reverse`. If you do not define `data-direction`, CloudCannon uses the `flex-direction` of your *Array Editable Region* when it has `display: flex`, and `column` otherwise.

<comp.CodeBlock language="Astro" source="TestimonialsLayout.astro">
``````````

<ul data-editable="array" data-prop="testimonials" data-direction="row"> /*1*/

``````````
<comp.Annotation number="1">

  The `data-direction` attribute tells CloudCannon this array is horizontal, so the *Context Menu* shows *Move left* and *Move right* options.

</comp.Annotation>
</comp.CodeBlock>

## Use the array length and item position

*Array* and *Array Item Editable Regions* provide two values from the structure of your array, rather than from your data. An *Array Editable Region* provides `@length`, the number of items in the array. An *Array Item Editable Region* provides `@index`, the position of that item. You can reference either value from an *Editable Region* nested inside, using `data-prop` or a `data-prop-*` HTML attribute.

<comp.CodeBlock language="Astro" source="TestimonialsLayout.astro">
``````````

<ul data-editable="array" data-prop="testimonials">
  {
    testimonials.map((testimonial, index) => (
      <li data-editable="array-item">
        <editable-component data-component="testimonial_card" data-prop-position="@index"> /*1*/
          <TestimonialCard {...testimonial} position={index} />
        </editable-component>
      </li>
    ))
  }
</ul>

``````````
<comp.Annotation number="1">

  The `data-prop-position` attribute passes the position of each array item to the registered `testimonial_card` component under the `position` key.

</comp.Annotation>
</comp.CodeBlock>

## Misconfigured Array Editable Regions

If your *Array Editable Region* is misconfigured, CloudCannon will replace it in the *Visual Editor* with a red *Error Card* headed *Failed to render array editable*, or *Failed to render array item* for a misconfigured *Array Item Editable Region*, followed by a message describing the problem. If CloudCannon cannot render a new array item, the heading is *Failed to render array editable region* for a simple array, or *Failed to render array item* for a complex array.

<comp.DocShot docshot_key="CloudCannon-Documentation-Visual-Editor-Array-Editable-Region-Error-Element" alt="A screenshot of an Error Card in the Visual Editor shows a message headed Failed to render array editable, explaining that the region received a value of type undefined instead of an array." title="A misconfigured Array Editable Region in the Visual Editor" type="ui-snippet"/>

*Array Editable Regions* are misconfigured if:

* You did not define the `data-prop` HTML attribute.
* The value at the `data-prop` path is not an array (e.g., it is a string, a number, or an object, or no value exists at that path).
* You have one or more orphaned *Array Item Editable Regions* whose nearest parent *Editable Region* is not an *Array Editable Region*.
* You did not define the `data-id-key` or `data-id` HTML attributes for a complex array.
* CloudCannon cannot render a new array item, because your *Array Editable Region* has no `<template>` element, no `data-component` or `data-component-key` HTML attribute, and no existing array item it can copy.
