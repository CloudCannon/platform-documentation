Connecting a GitHub *Git Repository* to your *Site* allows you to work on your website files locally and sync your changes to CloudCannon. CloudCannon also syncs file changes you make in CloudCannon back to GitHub.

How CloudCannon reaches your *Git Repositories* depends on which GitHub integration your *Organization* uses. On the new GitHub integration, your *Organization* attaches CloudCannon GitHub App installations and chooses which *Git Repositories* each one serves, so the *Repository* dropdown lists the allowed *Git Repositories* and there is no *Authorize* button. For more information, please read our documentation on [what GitHub installations are](/documentation/developer-articles/what-are-github-installations/). On the older integration, one person authorizes GitHub for the whole *Organization*, and the *Repository* dropdown lists every *Git Repository* that account can reach.

On the new GitHub integration, navigate to the *Syncing* page under *Site Settings*, select the *GitHub repository* option from the provider dropdown, then continue at the section on [connecting your Git Repository and branch](#connect-your-git-repository-and-branch). If the *Repository* dropdown is missing or your *Git Repository* is not listed, see the section on [changing which Git Repositories CloudCannon can access](#change-which-git-repositories-cloudcannon-can-access).

To connect a *Git Repository* on GitHub to your *Site* on the older integration:

1. Navigate to the *Syncing* page under *Site Settings*.
2. Select the *GitHub repository* option from the provider dropdown.
3. Click the *Authorize* button.

CloudCannon will redirect you to GitHub.

<comp.DocShot docshot_key="CloudCannon-Documentation-Site-Settings-Syncing-Select-GitHub-No-Authorization" alt="A screenshot of the Syncing page under Site Settings shows the GitHub repository option selected and an Authorize button." title="The Syncing page with GitHub selected" type="screenshot"/>

To give CloudCannon access to your GitHub account:

1. Enter your GitHub credentials to sign in.
2. Click the *Authorize CloudCannon* button.

If your *Organization* has no CloudCannon GitHub App installations yet, CloudCannon will take you to GitHub to install it. Otherwise, GitHub will redirect you back to the *Syncing* page. If you return without installing the GitHub App, click the *Grant access on GitHub* button on the *Syncing* page.

To install the CloudCannon GitHub App:

1. Choose whether to install the CloudCannon GitHub App on your personal GitHub account or on your GitHub organization.
2. Select the *All repositories* option or the *Only select repositories* option.
3. Click the *Install* button.

GitHub will redirect you back to the *Syncing* page, where you can select the *Git Repository* to connect.

## Connect your Git Repository and branch

<comp.Notice info_type="important">
  When you click the *Backup and Sync* button, CloudCannon will replace any existing files on your *Site* with the contents of the selected *Git Repository*. To cancel the process, exit the page instead.
</comp.Notice>

To connect your *Git Repository* and branch:

1. Select your *Git Repository* from the *Repository* dropdown.
2. Choose the *Use an existing branch* option or the *Create a new branch* option under the *Branch Setup* heading.
3. Pick your branch from the *Branch* dropdown. If you are creating a new branch, pick the branch to copy from the *Source branch* dropdown and enter a name in the *New branch name* field.
4. Click the *Backup and Sync* button.

CloudCannon will connect your *Site* to your GitHub *Git Repository*. CloudCannon pulls in changes you push to your *Git Repository*, and automatically commits and pushes any changes you make in CloudCannon.

## Change which Git Repositories CloudCannon can access

If your *Git Repository* does not appear in the *Repository* dropdown, the CloudCannon GitHub App may not have access to it.

On the new GitHub integration, click the *Manage access* link above the *Repository* dropdown. CloudCannon will open the *Manage repository access* modal, which lists the GitHub accounts your *Sites* use and the accounts your GitHub connection can reach, with a button for the fix on each, such as *Attach*, *Edit*, *Edit repositories*, or *Install on [Account Name]*. If your *Organization* has no allowed *Git Repositories* yet, the *Repository* dropdown is replaced by an *Attach an installation* button and an *Install on GitHub* button. The same controls appear on the *Create a Site* page. For the steps, please read our documentation on [attaching a GitHub installation](/documentation/developer-articles/attach-a-github-installation/).

Attaching an installation needs the `org:settings:git:provider:write` permission. Without it, the *Syncing* page shows *Ask an Organization Member to manage repository access* in place of the *Manage access* link, and you cannot attach an installation or change its *Git Repositories*.

On the older integration, to change which *Git Repositories* the GitHub App can access:

1. Click the *Manage access* link above the *Repository* dropdown. CloudCannon will open the *Manage repository access* modal, which lists your GitHub App installations.
2. Click the *Configure access* button on an installation to change its repository access on GitHub. To install the GitHub App on a different account instead, click the *Authorize a new GitHub account* button, check the account shown in the *Confirm account* modal, then click the *Authorize a new GitHub account* button again.

GitHub will redirect you back to the *Syncing* page once you save your changes.

## Upgrade to the new GitHub integration

The new GitHub integration lets you choose which *Git Repositories* your *Organization* can use, instead of reaching everything one person's GitHub connection can. When it is available to your *Organization*, the *GitHub* page under *Org Settings* and, for *Sites* that sync with GitHub, the *Syncing* page under *Site Settings* show members who can manage *Git Providers* a *New GitHub integration available* notice below the page heading, with an *Upgrade GitHub integration* button. You can switch back for 30 days after upgrading. For the steps, please read our documentation on [upgrading to the new GitHub integration](/documentation/developer-articles/upgrade-to-the-new-github-integration/).

<comp.DocShot docshot_key="CloudCannon-Documentation-Org-GitHub-V3-Upgrade-Banner" alt="A screenshot of the GitHub page under Org Settings shows the New GitHub integration available notice, which says to choose which repositories this Organization can use, with an Upgrade GitHub integration button above the tabs." title="The New GitHub integration available notice when the new integration is available" type="screenshot"/>

If your *Organization* authorized GitHub before the CloudCannon GitHub App existed and the new integration is not available to it yet, the *GitHub* page under *Org Settings* and, for *Sites* that sync with GitHub, the *Syncing* page under *Site Settings* show a notice with the same title and the same *Upgrade GitHub integration* button. That button moves your *Organization* to the CloudCannon GitHub App instead, and there is no switching back. When the migration completes, CloudCannon emails the members of your *Organization's* *Owners Permission Group* a link to revoke the previous authorization in GitHub.
