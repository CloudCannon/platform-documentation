You can forward the submissions an <comp.GlossaryTerm term="/user/glossary/i/inbox.yml">Inbox</comp.GlossaryTerm> receives to a Pipedream workflow, using an HTTP trigger and a *Pipedream* target.

A *Pipedream* target only accepts the HTTP trigger endpoint of a workflow, in the form `<endpoint>.m.pipedream.net`.

Create the workflow in Pipedream first, because the *Pipedream webhook URL* field needs its endpoint URL.

To get a Pipedream endpoint URL:

1. Sign in to Pipedream, or <a href="https://pipedream.com/auth/signup" target="_blank" rel="noopener noreferrer">create a Pipedream account</a>.
2. In the Pipedream dashboard, create a new workflow.
3. Select the *HTTP / Webhook* app as your trigger, then select the *New Requests* trigger.
4. Copy the endpoint URL Pipedream generates for your trigger.
5. Add the steps you want to run on each submission, then deploy your workflow.

Pipedream will start accepting requests at that endpoint, and run your workflow for each one.

Now add the target in CloudCannon. Select *Pipedream* in the *Choose your target type* dropdown and paste the endpoint URL into the *Pipedream webhook URL* field. For the full steps, please read our documentation on [adding a target to an Inbox](/documentation/developer-articles/add-a-target-to-an-inbox/).

<comp.DocShot docshot_key="CloudCannon-Documentation-Org-Settings-Forms-Add-Target-Pipedream-Modal" alt="A screenshot of the Add target modal shows Pipedream chosen as the target type and an endpoint URL in the Pipedream webhook URL field." title="The Add target modal" type="screenshot" />

CloudCannon will post each new submission to your HTTP trigger as JSON, and Pipedream will run the rest of your workflow with it.

For the *Spam protection* and *Links to attached files* options a target can carry, please read our documentation on [adding a target to an Inbox](/documentation/developer-articles/add-a-target-to-an-inbox/).
