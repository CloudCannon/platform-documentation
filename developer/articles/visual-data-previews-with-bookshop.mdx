<comp.Notice info_type="important">
  **For new *Sites*, we recommend *Editable Regions*.**

  *Editable Regions* are more closely integrated with Unified Configuration and live editing than the methods Bookshop uses to mark up and re-render your components. Bookshop continues to work, and *Sites* already built with it are unaffected. For more information, please read our documentation on [what Editable Regions are](/documentation/developer-articles/what-are-editable-regions/).
</comp.Notice>

<a href="https://github.com/CloudCannon/bookshop" target="_blank" rel="noopener noreferrer">Bookshop</a> is a component library system for static site generators. You write each component once, as a template plus a configuration file describing its fields, and Bookshop makes it available to your templates and to CloudCannon.

When a <comp.GlossaryTerm term="/user/glossary/s/site.yml">Site</comp.GlossaryTerm> using Bookshop is open in the <comp.GlossaryTerm term="/user/glossary/v/visual-editor.yml">Visual Editor</comp.GlossaryTerm>, Bookshop re-renders your components in the browser as their data changes, so the component on the page updates as its values are edited.

## What Bookshop sets up for you

Bookshop adds `data-cms-bind` attributes to the elements it renders, so you do not write *Visual Data Bindings* by hand. *Visual Data Bindings* are deprecated, and the bindings Bookshop generates are the same mechanism: CloudCannon maintains them and fixes critical bugs, but they receive no new features or further development. CloudCannon draws its editing overlays over those elements the same way it does for bindings you add yourself. For what those overlays do, please read our documentation on [what Visual Data Bindings are](/documentation/developer-articles/what-are-visual-data-bindings/).

Bookshop also handles the re-rendering itself, so you do not write the event-listening code described in our documentation on [what Visual Data Previews are](/documentation/developer-articles/what-are-visual-data-previews/).

## Using the Visual Editor API alongside Bookshop

Bookshop re-renders your components whether or not CloudCannon is present. It decides separately whether to add *Visual Data Bindings* to what it renders, by checking for `refreshInterface` on `window.CloudCannon`.

If your own integration code replaces that global, Bookshop keeps rendering but stops adding the bindings, so the editing overlays disappear from your components. The v1 *API Object* has no `refreshInterface`, so assigning it to `window.CloudCannon` is enough to turn the bindings off.

When you call `useVersion()` to get a v1 *API Object*, pass `true` as the second argument. CloudCannon then returns the object without assigning it to `window.CloudCannon`, leaving Bookshop's check intact.

<comp.CodeBlock language="javascript" source="script.js">
```
const api = window.CloudCannonAPI.useVersion('v1', true);
```
</comp.CodeBlock>

For more information, please read our documentation on [initializing the Visual Editor API](/documentation/developer-articles/initialize-the-visual-editor-api/).

## Getting help

If Bookshop's live rendering does not behave as described, <a href="https://cloudcannon.com/support/">contact support</a> with your *Site* name, the static site generator and Bookshop version your project uses, and what you expected to happen. You can also <a href="https://github.com/CloudCannon/bookshop/issues" target="_blank" rel="noopener noreferrer">raise an issue on the GitHub repository</a>.
