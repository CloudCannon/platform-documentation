Many WordPress concepts have an equivalent in CloudCannon, under a different name. This page lists the WordPress concepts you will meet during your migration, and what each one becomes on your new <comp.GlossaryTerm term="/user/glossary/s/site.yml">Site</comp.GlossaryTerm>. The rest of this guide uses the CloudCannon names.

This page is also useful for the people who edited your WordPress site, as they learn to edit in CloudCannon.

## Content

WordPress stores content in a database. CloudCannon edits content stored as files in your <comp.GlossaryTerm term="/user/glossary/g/git-repository.yml">Git Repository</comp.GlossaryTerm>, and your <comp.GlossaryTerm term="/user/glossary/s/ssg.yml">Static Site Generator</comp.GlossaryTerm> (SSG) builds your website from those files.

* **Post type** — A <comp.GlossaryTerm term="/user/glossary/c/collection.yml">Collection</comp.GlossaryTerm>, a folder of related files with a similar format. Posts, pages, and each custom post type usually become one *Collection* each.
* **Post or page** — A Markdown file in a *Collection*. The body of the file holds the post content, and the <comp.GlossaryTerm term="/user/glossary/f/front-matter.yml">front matter</comp.GlossaryTerm> at the top of the file holds its title, date, and other details.
* **Custom field** — A front matter key. CloudCannon shows each key as an <comp.GlossaryTerm term="/user/glossary/i/input.yml">input</comp.GlossaryTerm>, such as a text field, a date picker, or a dropdown.
* **ACF field group** — The input configuration for a *Collection*, set with the `_inputs` key in your <comp.GlossaryTerm term="/user/glossary/c/configuration-files.yml">CloudCannon Configuration File</comp.GlossaryTerm>, and a <comp.GlossaryTerm term="/user/glossary/s/schema.yml">Schema</comp.GlossaryTerm> that gives each new file the keys it needs.
* **Repeater and Flexible Content fields** — Array inputs. For items that can each have a different shape, a <comp.GlossaryTerm term="/user/glossary/s/structure.yml">Structure</comp.GlossaryTerm> defines each shape.
* **Taxonomy, such as categories and tags** — A front matter key with a select or multiselect input. The list of terms lives in a data file, defined as a <comp.GlossaryTerm term="/user/glossary/d/dataset.yml">Dataset</comp.GlossaryTerm>.
* **Media Library** — An uploads folder in your *Git Repository*, where CloudCannon saves the images and files your team uploads. Instead of the uploads folder, a developer can connect a <comp.GlossaryTerm term="/user/glossary/d/dam.yml">DAM</comp.GlossaryTerm>, a separate service that stores your media files.
* **Draft** — A file whose front matter marks it as a draft, such as `draft: true`. Your SSG decides whether it builds draft files.
* **Scheduled post** — A file with a future date, and a scheduled build that rebuilds your website at that time. For more information, please read our documentation on [scheduling your next build automatically](/documentation/developer-articles/scheduling-your-next-build-automatically/).

## Editing

WordPress edits a post's content and its custom fields on one screen. CloudCannon has several editing interfaces, and which ones appear for a *Collection* depends on how your *Site* is configured.

* **Classic Editor** — The <comp.GlossaryTerm term="/user/glossary/c/content-editor.yml">Content Editor</comp.GlossaryTerm>, a rich text editor for Markdown files. The <comp.GlossaryTerm term="/user/glossary/d/data-editor.yml">Data Editor</comp.GlossaryTerm> edits front matter and data files, and the <comp.GlossaryTerm term="/user/glossary/s/source-editor.yml">Source Editor</comp.GlossaryTerm> shows the raw contents of a file.
* **Block editor** — For a page built from blocks, an array input whose items are *Structures*, one for each kind of block. Your team adds, removes, and reorders the items in the *Data Editor*, or directly on the page in the *Visual Editor*.
* **Preview** — The <comp.GlossaryTerm term="/user/glossary/v/visual-editor.yml">Visual Editor</comp.GlossaryTerm>, which shows each page as your visitors will see it. A developer adds <comp.GlossaryTerm term="/user/glossary/e/editable-region.yml">Editable Regions</comp.GlossaryTerm> to your templates so your team can edit content directly on the page.
* **Posts and Pages menus** — The <comp.GlossaryTerm term="/user/glossary/s/site-navigation.yml">Site Navigation</comp.GlossaryTerm>, which lists your *Collections*. Each *Collection* opens in a <comp.GlossaryTerm term="/user/glossary/c/collection-browser.yml">Collection Browser</comp.GlossaryTerm>, where you can add, open, and delete files.
* **Update or Publish button** — The *Save* button, which saves your changes to your *Git Repository*. If your *Site* uses a <comp.GlossaryTerm term="/user/glossary/p/publishing-workflow.yml">publishing workflow</comp.GlossaryTerm>, your changes save to a draft *Site*, and publishing moves those changes to your live *Site*.
* **Revisions** — The history of each file in your *Git Repository*. Every save is a commit, so your <comp.GlossaryTerm term="/user/glossary/g/git-provider.yml">Git Provider</comp.GlossaryTerm> keeps every earlier version.

## Site structure

WordPress builds each page from your theme and plugins when a visitor requests it. Your SSG builds every page ahead of time from your templates.

* **Theme** — The layouts and templates in your SSG project, which display your content.
* **Plugin** — A feature of your SSG, a CloudCannon feature, or a third-party service. For example, a contact form plugin can become a form that sends submissions to an <comp.GlossaryTerm term="/user/glossary/i/inbox.yml">Inbox</comp.GlossaryTerm> in CloudCannon.
* **Permalink settings** — The URL pattern your SSG templates produce, and the `url` key of each *Collection*, which tells CloudCannon where each file ends up. Redirects from old URLs go in a routing file.
* **Menus** — A data file that lists the links in each menu, which your templates read. Your team edits it in the *Data Editor*.
* **Dashboard** — The <comp.GlossaryTerm term="/user/glossary/s/site-dashboard.yml">Site Dashboard</comp.GlossaryTerm>, which shows the status of your *Site*, its builds, and its in-app guides.

## People

* **WordPress user** — An <comp.GlossaryTerm term="/user/glossary/o/organization-member.yml">Organization Member</comp.GlossaryTerm>, a person with a CloudCannon account in your <comp.GlossaryTerm term="/user/glossary/o/organization.yml">Organization</comp.GlossaryTerm>. WordPress accounts do not move to CloudCannon, so you add each person again, and each person can add a seat to your bill. For more information, please read our documentation on [adding an Organization Member to your Organization](/documentation/user-articles/add-an-organization-member-to-your-organization/).
* **Role, such as Editor or Administrator** — A <comp.GlossaryTerm term="/user/glossary/p/permission-group.yml">Permission Group</comp.GlossaryTerm>, which sets what its members can do. Every *Organization* has the *Owners*, *Developers*, *Technical Editors*, *Editors*, and *Billing* <comp.GlossaryTerm term="/user/glossary/d/default-permission-groups.yml">Default Permission Groups</comp.GlossaryTerm>. For what each group can do, please read our documentation on [what Default Permission Groups are](/documentation/user-articles/what-are-default-permission-groups/).
