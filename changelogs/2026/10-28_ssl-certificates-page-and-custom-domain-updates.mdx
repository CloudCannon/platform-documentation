title: SSL Certificates page and Custom Domain updates
date: 2026-10-28T12:00:00+13:00
---
This release added the *SSL Certificates* page under *Org Settings*, offered the CNAME record that lets Cloudflare renew a wildcard certificate on its own as soon as your domain uses external DNS, and moved the HTTP to HTTPS redirect for a *Site* to its *Custom Domain* page.

It also changed how a *Custom Domain* is added to a *Site* and how redirect subdomains choose their target, changed the domain filters of the *Client Organizations Browser* to check subdomains rather than *Sites*, and deprecated the *Site* SSL endpoints in the CloudCannon API in favor of the subdomain endpoints.

## Features & Improvements

* Added the *SSL Certificates* page under *Org Settings*, allowing you to upload, review, and remove the SSL certificates your *Organization* uses. Each certificate has its own page, which shows when it expires, the domains it covers, and the subdomains that serve HTTPS with it, including redirect subdomains. For more information, please read our documentation on [uploading a certificate from Org Settings](/documentation/developer-articles/add-a-custom-ssl-certificate/#upload-a-certificate-from-org-settings).
  * Each certificate shows a *Valid*, *Expires soon*, *Expired*, or *Renews automatically* status. An uploaded certificate shows *Expires soon* from 30 days before it expires.
  * CloudCannon only removes a certificate that no subdomain uses. To remove a certificate in use, choose a different SSL certificate in the *HTTPS for [Subdomain]* modal of each subdomain that uses it first.
  * Viewing the page needs the `org:settings:certificate:read` permission, and adding or removing a certificate needs the `org:settings:certificate:write` permission.
* Changed the *Other subdomains* block in the *HTTPS* section of your *Base Domain*, and the *DNS* tab of the *Domain* page, to offer the CNAME record that lets Cloudflare renew the wildcard certificate on its own whenever your domain uses external DNS, rather than only while a renewal is waiting for TXT records. For more information, please read our documentation on [letting Cloudflare renew the wildcard certificate on its own](/documentation/developer-articles/add-an-auto-generated-ssl-certificate/#let-cloudflare-renew-the-wildcard-certificate-on-its-own).
* Moved the HTTP to HTTPS redirect from the *Routing* page under *Site Settings* to the *HTTPS* section of the *Custom Domain* page, where it applies to every *Site* on the subdomain. The *Routing* page links to the new location.
* Changed adding a *Custom Domain* to a *Site* to require its *Base Domain* to be connected to your *Organization* first. For more information, please read our documentation on [connecting a Custom Domain to your Organization](/documentation/developer-articles/connect-a-custom-domain-to-your-organization/).
* Changed redirect subdomains to require a target on one of your own *Base Domains* to be an existing subdomain. If the target isn't set up yet, CloudCannon asks you to add it as a subdomain first. For more information, please read our documentation on [managing redirect subdomains](/documentation/developer-articles/manage-redirect-subdomains/).
* Changed the domain filters in the *Client Organizations Browser* to check the subdomains of each client's *Custom Domains* rather than its *Sites*. The *Sites Not Resolving* filter is now *Subdomains Not Pointing*.
* Changed every *Base Domain* that was set to use CloudCannon DNS, but whose nameservers never pointed at CloudCannon and were first checked more than 30 days ago, to use external DNS. For more information, please read our documentation on [configuring external DNS](/documentation/developer-articles/configure-external-dns/).
* Deprecated the *Site* SSL endpoints and fields in the CloudCannon API. They still work, but each has a replacement on the subdomain a *Site* is served on, and the full *Site* response includes a `subdomain_uuid` field to find it. For more information, please read our [API reference](/documentation/developer-reference/api/).
  * `PUT /api/v0/sites/{site_uuid}/ssl`, `DELETE /api/v0/sites/{site_uuid}/ssl`, and `PUT /api/v0/sites/{site_uuid}/ssl/cloudflare` are replaced by `PUT /api/v0/base-domains/{base_domain_uuid}/subdomains/{subdomain_uuid}`.
  * `POST /api/v0/sites/{site_uuid}/ssl/auto` and `POST /api/v0/sites/{site_uuid}/ssl/cloudflare` are replaced by `POST /api/v0/base-domains/{base_domain_uuid}/subdomains/{subdomain_uuid}/ssl/retry`.
  * `POST /api/v0/sites/{site_uuid}/domain/prioritise` is replaced by `POST /api/v0/base-domains/{base_domain_uuid}/subdomains/{subdomain_uuid}/fallback`.
  * The `hosting_choice`, `force_ssl`, `auto_generate_ssl`, and `ssl_certificate_id` fields on `PUT /api/v0/sites/{site_uuid}/hosting` are replaced by the same fields on `PUT /api/v0/base-domains/{base_domain_uuid}/subdomains/{subdomain_uuid}`. On a *Site* without a *Custom Domain*, these fields return an error unless the value matches the one the *Site* already has.
* Removed the `sites` field from the SSL certificates listed by `GET /api/v0/orgs/{org_uuid}/ssl-certificates`, and deprecated it on `GET /api/v0/ssl-certificates/{ssl_certificate_uuid}`. Added `GET /api/v0/ssl-certificates/{ssl_certificate_uuid}/subdomains`, allowing you to list the subdomains that use a certificate, including redirect subdomains, on the *Base Domains* you can read. Each SSL certificate also has a new `hostnames` field listing the domains it covers.
* Changed moving a *Base Domain* from the legacy CloudCannon DNS to the new CloudCannon DNS to need permission to edit its DNS as well as its settings, in the app and through `PUT /api/v0/base-domains/{base_domain_uuid}/migrate`. For more information, please read our documentation on [moving from the legacy CloudCannon DNS](/documentation/developer-articles/configure-cloudcannon-dns/#move-from-the-legacy-cloudcannon-dns).
* Changed retrying a certificate through `POST /api/v0/base-domains/{base_domain_uuid}/subdomains/{subdomain_uuid}/ssl/retry`, and the deprecated *Site* retry endpoints, to work at most once a minute for each subdomain.
* Changed `GET /api/v0/orgs/{org_uuid}/base-domains` to return the `found_name_servers`, `name_servers_checked_at`, `name_server_check_failed_at`, `disconnect_blockers`, and `wildcard_certificate` fields empty, so the list loads faster. `GET /api/v0/base-domains/{base_domain_uuid}` still returns them.
