title: SSL Certificates page and Custom Domain updates
date: 2026-10-28T12:00:00+13:00
---
This release added the *SSL Certificates* page under *Org Settings*, offered the CNAME record that lets Cloudflare renew a wildcard certificate on its own as soon as your domain uses external DNS, and moved the HTTP to HTTPS redirect for a *Site* to its *Custom Domain* page.

It also changed how a *Custom Domain* is added to a *Site* and how redirect subdomains choose their target, changed the domain filters of the *Client Organizations Browser* to check subdomains rather than *Sites*, and deprecated the *Site* SSL endpoints in the CloudCannon API in favor of the subdomain endpoints.

## Features & Improvements

* Added the *SSL Certificates* page under *Org Settings*, allowing you to upload, review, and remove the SSL certificates your *Organization* uses. Each certificate has its own page, which shows when it expires, the domains it covers, and the subdomains that serve HTTPS with it, including redirect subdomains. For more information, please read our documentation on [uploading a certificate from Org Settings](/documentation/developer-articles/add-a-custom-ssl-certificate/#upload-a-certificate-from-org-settings).
  * Each certificate shows a *Valid*, *Expires soon*, *Expired*, *Removing*, or *Renews automatically* status. An uploaded certificate shows *Expires soon* from 30 days before it expires.
  * Removing a certificate switches every subdomain that uses it to the *Let CloudCannon issue and renew it* option. Each subdomain keeps serving the certificate until CloudCannon issues its own, so HTTPS stays on, and CloudCannon then deletes the certificate. For more information, please read our documentation on [removing an uploaded certificate](/documentation/developer-articles/add-a-custom-ssl-certificate/#remove-an-uploaded-certificate).
  * Viewing the page needs the `org:settings:certificate:read` permission, and adding or removing a certificate needs the `org:settings:certificate:write` permission.
* Added an email 14 days and three days before an SSL certificate you uploaded expires, allowing you to replace it before visitors see a security warning. It goes to everyone who can edit the settings of a *Base Domain* with a subdomain that still uses the certificate. If a subdomain still uses it when it expires, CloudCannon switches that subdomain to the *Let CloudCannon issue and renew it* option. For more information, please read our documentation on [what happens when an uploaded certificate expires](/documentation/developer-articles/add-a-custom-ssl-certificate/#when-an-uploaded-certificate-expires).
* Changed the *Other subdomains* block in the *HTTPS* section of your *Base Domain*, and the *DNS* tab of the *Domain* page, to offer the CNAME record that lets Cloudflare renew the wildcard certificate on its own whenever your domain uses external DNS, rather than only while a renewal is waiting for TXT records. For more information, please read our documentation on [letting Cloudflare renew the wildcard certificate on its own](/documentation/developer-articles/add-an-auto-generated-ssl-certificate/#let-cloudflare-renew-the-wildcard-certificate-on-its-own).
* Moved the HTTP to HTTPS redirect from the *Routing* page under *Site Settings* to the *HTTPS* section of the *Custom Domain* page, where it applies to every *Site* on the subdomain. The *Routing* page links to the new location.
* Added a *Minimum TLS version* dropdown to the *HTTPS for [Subdomain]* modal, allowing you to raise the minimum TLS version of one subdomain above the minimum for its *Custom Domain*. For more information, please read our documentation on [raising the minimum TLS version for one subdomain](/documentation/developer-articles/increase-the-minimum-tls-version-for-your-domains/#raise-the-minimum-tls-version-for-one-subdomain).
* Changed the TXT records for the first wildcard certificate of a *Base Domain* on external DNS to show as optional. The setup guide no longer asks for them, the *DNS* tab lists them under *Wildcard certificate records (optional)* until the first certificate is issued, and the *HTTPS* section of the subdomain page for your *Base Domain* links to them rather than repeating them. For more information, please read our documentation on [renewing the wildcard certificate on external DNS](/documentation/developer-articles/add-an-auto-generated-ssl-certificate/#renew-the-wildcard-certificate-on-external-dns).
* Changed the *DNS* tab of the *Domain* page to show the same setup steps as the *Summary* tab while CloudCannon DNS is being set up, and to give the nameservers for CloudCannon DNS and external DNS their own section with a documentation link and a short explanation. For more information, please read our documentation on [configuring CloudCannon DNS](/documentation/developer-articles/configure-cloudcannon-dns/) and [configuring external DNS](/documentation/developer-articles/configure-external-dns/).
  * The nameserver table compares the nameservers your registrar lists with the ones CloudCannon needs in one row. The check passes only when the lists match exactly, and the status names any extra nameservers to remove.
  * *Required records* lists only the records still to add, and shows a success message once every required record is connected. It is hidden while CloudCannon waits for your nameservers.
  * The wildcard record table is titled *Wildcard record (optional)*, and has the same *I've updated it* button as the other records, after which CloudCannon checks it hourly for seven days.
  * The CNAME record that lets Cloudflare renew the wildcard certificate on its own is in its own *Automatic renewal record (optional)* table, which goes away once CloudCannon finds the record.
* Added a footer to every DNS table that CloudCannon checks, allowing you to see how often CloudCannon checks, when it last checked, and the history of those checks. The footer holds the *Check now* button, which is unavailable for a minute after each check. The *DNS* tab adds a history of nameserver checks.
* Changed the copy buttons on the *Domain* page and the subdomain page to icon buttons, which show *Copied!* after you click them.
* Changed the *Summary* tab of the *Domain* page to show how many subdomains need attention, with a link to the *Subdomains* tab filtered to those subdomains. The DNS provider and nameserver rows are now one row, and the setup guide lists the records to add before the nameservers.
* Changed the *Custom Domain* page under *Site Settings* to show the settings of the subdomain the *Site* is on, under *Subdomain settings*, allowing you to change its hosting, HTTPS, and DNS without leaving the *Site*. For more information, please read our documentation on [adding a Custom Domain to your Site](/documentation/developer-articles/add-a-custom-domain-to-your-site/).
* Changed lowering the minimum TLS version for a *Custom Domain* to leave its subdomains as they are, unless you check the *Also lower* checkbox. The subdomain page for your *Base Domain* also has its own *Minimum TLS version* dropdown. For more information, please read our documentation on [increasing the minimum TLS version for your domains](/documentation/developer-articles/increase-the-minimum-tls-version-for-your-domains/).
* Changed switching a subdomain from an uploaded certificate to the *Let CloudCannon issue and renew it* option to issue CloudCannon's certificate straight away, rather than close to the uploaded certificate's expiry.
* Changed the tables on the *Domain* page to stack each row on narrow screens, and long domain names to wrap rather than overflow.
* Changed adding a *Custom Domain* to a *Site* to require its *Base Domain* to be connected to your *Organization* first. For more information, please read our documentation on [connecting a Custom Domain to your Organization](/documentation/developer-articles/connect-a-custom-domain-to-your-organization/).
* Changed redirect subdomains to require a target on one of your own *Base Domains* to be an existing subdomain. If the target isn't set up yet, CloudCannon asks you to add it as a subdomain first. For more information, please read our documentation on [managing your Redirect Subdomains](/documentation/developer-articles/manage-your-redirect-subdomains/).
* Changed the domain filters in the *Client Organizations Browser* to check the subdomains of each client's *Custom Domains* rather than its *Sites*. The *Sites Not Resolving* filter is now *Subdomains Not Pointing*.
* Changed every *Base Domain* that was set to use CloudCannon DNS, but whose nameservers never pointed at CloudCannon and were first checked more than 30 days ago, to use external DNS. For more information, please read our documentation on [configuring external DNS](/documentation/developer-articles/configure-external-dns/).
* Deprecated the *Site* SSL endpoints and fields in the CloudCannon API. They still work, but each has a replacement on the subdomain a *Site* is served on, and the full *Site* response includes a `subdomain_uuid` field to find it. For more information, please read our [API reference](/documentation/developer-reference/api/).
  * `PUT /api/v0/sites/{site_uuid}/ssl`, `DELETE /api/v0/sites/{site_uuid}/ssl`, and `PUT /api/v0/sites/{site_uuid}/ssl/cloudflare` are replaced by `PUT /api/v0/base-domains/{base_domain_uuid}/subdomains/{subdomain_uuid}`.
  * `POST /api/v0/sites/{site_uuid}/ssl/auto` and `POST /api/v0/sites/{site_uuid}/ssl/cloudflare` are replaced by `POST /api/v0/base-domains/{base_domain_uuid}/subdomains/{subdomain_uuid}/ssl/retry`.
  * `POST /api/v0/sites/{site_uuid}/domain/prioritise` is replaced by `POST /api/v0/base-domains/{base_domain_uuid}/subdomains/{subdomain_uuid}/fallback`.
  * The `hosting_choice`, `force_ssl`, `auto_generate_ssl`, and `ssl_certificate_id` fields on `PUT /api/v0/sites/{site_uuid}/hosting` are replaced by the same fields on `PUT /api/v0/base-domains/{base_domain_uuid}/subdomains/{subdomain_uuid}`. On a *Site* without a *Custom Domain*, these fields return an error unless the value matches the one the *Site* already has.
* Removed the `sites` field from the SSL certificates listed by `GET /api/v0/orgs/{org_uuid}/ssl-certificates`, and deprecated it on `GET /api/v0/ssl-certificates/{ssl_certificate_uuid}`. Added `GET /api/v0/ssl-certificates/{ssl_certificate_uuid}/subdomains`, allowing you to list the subdomains that use a certificate, including redirect subdomains, on the *Base Domains* you can read. Each SSL certificate also has a new `hostnames` field listing the domains it covers.
* Changed moving a *Base Domain* from the legacy CloudCannon DNS to the new CloudCannon DNS to need permission to edit its DNS as well as its settings, in the app and through `PUT /api/v0/base-domains/{base_domain_uuid}/migrate`. For more information, please read our documentation on [moving from the legacy CloudCannon DNS](/documentation/developer-articles/configure-cloudcannon-dns/#move-from-the-legacy-cloudcannon-dns).
* Changed retrying a certificate through `POST /api/v0/base-domains/{base_domain_uuid}/subdomains/{subdomain_uuid}/ssl/retry`, and the deprecated *Site* retry endpoints, to work at most once a minute for each subdomain.
* Added `GET /api/v0/base-domains/{base_domain_uuid}/dns/checks`, allowing you to list the nameserver checks for a *Base Domain*, most recent first. Added `POST /api/v0/base-domains/{base_domain_uuid}/dns/wildcard-record-updated`, allowing you to mark the optional wildcard record as added, and the `wildcard_record_checked_at`, `wildcard_record_found`, and `wildcard_record_updated_at` fields on each *Base Domain*.
* Changed `DELETE /api/v0/ssl-certificates/{ssl_certificate_uuid}` to remove a certificate that subdomains still use, rather than refuse it. It returns `202` with the certificate while subdomains still serve it, and `204` once the certificate is deleted. Each SSL certificate has a new `removal_requested_at` field, and `GET /api/v0/orgs/{org_uuid}/ssl-certificates` has a new `removing` filter.
* Changed `GET /api/v0/orgs/{org_uuid}/base-domains` to return the `found_name_servers`, `name_servers_checked_at`, `name_server_check_failed_at`, `disconnect_blockers`, and `wildcard_certificate` fields empty, so the list loads faster. `GET /api/v0/base-domains/{base_domain_uuid}` still returns them.
